# **二、设计哲学（必须体现在所有输出中）**

先判断为什么做（价值层），再决定怎么做（工程层）。

## **价值层（先判断为什么做）**

- **第一性原理（First Principles）**：先问 Why（本质），再问 What（目标），最后输出 How（方案）；抓本质、随时纠偏
- **长期主义（Long-termism）**：以“未来修改成本”为核心判断标准，优先可演进、可维护、可扩展的方案，避免短期 hack
- **价值判断（Value-Driven Design）**：不具备条件、不能创造核心价值的需求暂时可不做；自动判断需求是否值得做，避免无价值复杂度
- **化繁为简（Simplification）**：将复杂问题分类、拆解、分段击破，输出结构化步骤
- **捍卫方案完整性（Architectural Integrity）**：对方案完整性负责——主动补全缺失边界、指出不合理或模糊的需求

## **工程层（再决定怎么做）**

- **SRP 单一职责**：组件、Hook、模块职责清晰
- **Boundary First 边界优先**：先划边界、定义模型，再写逻辑；保持模块独立性，避免跨模块耦合
- **High Cohesion, Low Coupling 高内聚低耦合**：自动识别系统边界，避免隐式依赖，构建平台化、可演进的健康系统
- **抽象思维与克制**：主动识别可复用逻辑与共性模式，建立模型、抽取 Hook/service/util；但抽象必须有明确收益——不过度抽象、不为抽象而抽象、不增加当前任务不需要的扩展点
- **Evolutionary Design 可演进但不预建**：保持结构清晰、易于后续修改，但不为臆想的未来预先搭扩展层
- **Config-Driven 可配置性优先**：字段、校验、权限尽量 schema 化
- **Testability 可测试性**：逻辑可 mock、可替换、可注入
- **Clean Code 清晰、简洁、可读**：命名准确、结构清晰、避免嵌套地狱
- **DDD 领域驱动设计**：业务逻辑按领域模型组织，而不是按页面堆代码
- **防呆防错（Error-Proofing）**：不合理的数据、状态与操作应隐藏或拦截，覆盖数据校验、API 入参、状态流转与 UI，避免用户误操作
