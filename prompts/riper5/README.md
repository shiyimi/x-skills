# RIPER-E: The Premier AI Programming Assistant Operating Protocol

## 1. Core Feature: Intelligent Adaptive Workflow

The core of RIPER-E is its **intelligent adaptation** mechanism. It moves away from the rigid, linear processes of traditional AI assistants and automatically selects the optimal execution path based on task complexity:

-   **Simple Tasks** → Direct execution for rapid response, avoiding over-engineering.
-   **Complex Tasks** → A full analysis cycle to ensure in-depth review and quality.

This adaptive approach unifies efficiency and quality, resolving the common dilemma of how an AI assistant should handle tasks of varying complexity.

## 2. Protocol Introduction

Welcome to **RIPER-E**, the operating protocol for top-tier AI programming assistants. It provides a framework to ensure that powerful AI capabilities are transformed into high-quality, reliable, and maintainable software solutions.

The primary goal of this protocol is to mitigate a critical risk: an AI assistant that is *too* eager, implementing changes without sufficient communication or disrupting existing logic based on flawed assumptions. RIPER-E prevents this by establishing a structured, adaptive workflow.

## 3. Protocol Workflow

The RIPER-E protocol is structured around a series of modes, each with a specific purpose. The workflow is not always linear but is determined by the Triage assessment.

### Mode Overview

| Mode         | Core Purpose                               | Key Activities                       | Main Output                            |
| :----------- | :----------------------------------------- | :----------------------------------- | :------------------------------------- |
| **TRIAGE**   | Assess task and determine the optimal path | Six-dimensional evaluation, risk analysis | Structured assessment report, mode decision |
| **RESEARCH** | Gather information and perform deep analysis | Read code, analyze dependencies, identify constraints | Observations, clarifying questions     |
| **INNOVATE** | Brainstorm solutions and evaluate options  | Explore multiple solutions, compare pros and cons | Recommended solution, high-level implementation summary |
| **PLAN**     | Create a detailed, executable plan         | Define technical specs, create a to-do list | Detailed technical specifications, atomic to-do list |
| **EXECUTE**  | Implement the plan with precision          | Write code, execute commands, update status | Fully implemented code or operational results |
| **REVIEW**   | Verify results and ensure consistency      | Compare plan vs. implementation, check code quality | Review conclusion (Pass/Fail)          |

### Mode Transition Rules

-   **Complex Task Flow**: `TRIAGE` → `RESEARCH` → `INNOVATE` → `PLAN` → `EXECUTE` → `REVIEW`
-   **Simple Task Flow**: `TRIAGE` → `EXECUTE` → `REVIEW`

## 4. Core Principles

All operations under this protocol are guided by a set of core principles to ensure depth, systematic thinking, and creativity. These include:

-   **Six Foundational Principles**: Deep Thinking, Systems Thinking, Dialectical Thinking, Innovative Thinking, Critical Thinking, and First-Principles Thinking.
-   **Mode-Specific Protocols**: Each mode has its own set of rules governing allowed and prohibited actions to ensure focus and quality at every stage.
-   **Plan Fidelity**: In `EXECUTE` mode, the plan must be followed with 100% fidelity. Any deviation must be flagged and addressed in the `REVIEW` mode.

## 5. Getting Started

To begin, an AI assistant operating under RIPER-E will start in **`TRIAGE`** mode for any new task. It will then perform a six-dimensional assessment to determine the best path forward.

For more detailed information on each mode, the evaluation criteria, and other guidelines, please refer to the full `RIPER-E-Hybrid.md` documentation.
