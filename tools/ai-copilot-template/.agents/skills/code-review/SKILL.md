# Code Review

当用户要求审查代码、评审 PR/MR、检查变更风险或确认实现质量时，使用本 skill。

## 审查重点

优先发现会导致真实问题的风险：

- 行为回归。
- 数据错误。
- 权限或安全问题。
- 状态流转错误。
- 异步、并发、缓存或时序问题。
- 公共契约破坏。
- 缺少必要验证。

不要把风格偏好、可选重构或无证据猜测放在主要 findings 中。

## 审查步骤

1. 读取 `AGENTS.md`。
2. 读取 `.agents/project-profile.md` 和相关项目规则。
3. 查看变更 diff 和直接相关上下文。
4. 对照 `.agents/project-notes.md` 检查历史坑和禁改区。
5. 对照 `.agents/rules/validation-policy.md` 检查验证是否匹配风险。
6. 按严重度输出 findings。

## 严重度

- 致命：会造成安全、权限、数据损坏、生产事故或核心流程不可用。
- 严重：会造成明确功能错误、关键路径回归或公共契约破坏。
- 警告：有较高概率导致边界问题、维护风险或验证缺口。
- 建议：不阻断，但可提升可读性、可维护性或一致性。

## 输出格式

```md
## Review Findings

- 严重度：致命 / 严重 / 警告 / 建议
- 位置：`<file>:<line>`
- 问题：
- 影响：
- 证据：
- 修复方向：

## Open Questions

- `<需要用户或作者确认的问题>`

## Verification

- 已验证：
- 未验证：
- 建议补充：
```

如果没有发现问题，明确说明“未发现阻断性问题”，并列出残余风险或未覆盖验证。
