# Requirement Review

当任务涉及实现、重构、调试、流程变更、权限、安全、数据一致性或跨模块影响时，先执行需求审查。

## 目标

- 确认用户目标是否成立。
- 确认前提、边界、输入、输出和成功标准是否清楚。
- 识别风险半径和复杂性变化。
- 在目标错误、前提不足或风险不可控时阻断。

## 步骤

1. 读取 `AGENTS.md`。
2. 读取 `.agents/project-profile.md`。
3. 需要业务或架构上下文时，读取 `.agents/project-overview.md`。
4. 需要历史坑或禁改区时，读取 `.agents/project-notes.md`。
5. 按 S/M/L 判断任务风险。
6. 判断是否可以直接实施，是否需要用户确认。

## 输出格式

```md
## Step 1: 需求审查

- 裁决：分级 S/M/L · 边界
- 关键发现：
- 风险与前提：
- 复杂性变化：
- 结论：可执行 / 有条件 / 需补充 / 建议调整 / 停止
```

## 阻断条件

遇到以下情况必须暂停：

- 目标明显错误或与项目事实冲突。
- 关键前提无法验证。
- 影响范围无法安全界定。
- 需要不可逆操作但缺少回滚路径。
- 涉及生产、安全、权限、密钥或公开接口但用户未确认。
