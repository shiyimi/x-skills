# AGENTS.md

> 本文件是项目级 AI 协作入口。做任何编码、缺陷修复、重构、文档治理或测试补充前，先读完本文，再读取 `.agents/index.md`，然后按任务类型按需加载具体文件。

## 上下文加载原则

默认只加载两层入口：

1. `AGENTS.md`
2. `.agents/index.md`

除非任务命中 `.agents/index.md` 中的路由规则，否则不要一次性读取全部 `.agents/` 文件。

## 按需加载

- 需要项目技术栈、目录、命令或编码约定时，读取 `.agents/projects/profile.md`。
- 需要业务背景、模块边界、架构关系或核心数据流时，读取 `.agents/projects/overview.md`。
- 需要历史坑、禁改区、推荐参考或已知基线问题时，读取 `.agents/projects/notes.md`。
- 需要通用工程原则和风险红线时，读取 `.agents/core.md`。
- 需要验证命令或完成口径时，读取 `.agents/validation.md`。
- 需要需求审查时，读取 `.agents/skills/requirement-review/SKILL.md`。
- 需要代码审查时，读取 `.agents/skills/code-review/SKILL.md`。

## 基本原则

- 先明确目标、边界、风险和验证方式，再实施。
- 优先最小改动，不静默扩大范围。
- 优先复用项目现有结构、命名、组件、工具和验证命令。
- 未读取相关上下文前，不臆造项目技术栈、目录、接口、命令或业务规则。
- 未执行与改动范围匹配的验证前，不宣称开发完成、修复完成或验证通过。
- 遇到目标错误、前提不足、证据冲突或风险不可控时，必须暂停并说明替代路径。

## 专项路由

优先以 `.agents/index.md` 为路由依据。只有当任务需要更具体上下文时，再读取对应文件。

## Git 与安全规则

- 不自动暂存、提交、推送，除非用户明确要求。
- 不执行会丢失改动的 Git 或文件系统操作，除非用户明确确认。
- 不把密钥、Token、Cookie、私有证书、生产地址或敏感配置写入仓库。
- 不删除 `.agents/` 目录或其中的文件，除非用户明确要求进行 AI 协作资产治理。
