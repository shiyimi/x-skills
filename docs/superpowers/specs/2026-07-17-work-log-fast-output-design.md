# Work Log 快速输出与自动保存设计

## 目标

调整 `work-log` 的执行顺序，使标准信息在任何 IMA 调用之前先展示给用户，便于立即填写部门日志；展示完成后，在同一轮任务中自动继续保存到 IMA，不等待用户确认。

## 行为契约

流程固定为：

`信息处理 -> 立即展示标准信息 -> 自动保存到 IMA -> 展示保存结果`

1. 日期必须来自用户输入或明确上下文。日期不明确或原始信息不足时，展示待确认结果并停止，不调用 IMA。
2. 标准信息生成后，必须先发送一条独立消息。该消息只包含处理结果、日期和标准信息，不包含尚未发生的保存结果。
3. 第一条消息发送后，不等待用户确认，立即执行现有 IMA 验证、读取、同日去重和追加流程。
4. IMA 操作完成后发送最终结果，准确说明保存成功、跳过重复或保存失败，并再次包含标准信息，确保最终可见结果完整。
5. IMA 失败不得回溯改变已经完成的信息处理状态，也不得影响用户使用首次输出填写部门日志。

## 所有权与边界

- `references/information-processing.md` 继续拥有事实重组和标准信息格式规则。
- `SKILL.md` 拥有阶段顺序、阶段进入条件、消息模板和 IMA 副作用边界。
- `ima-skill` 继续拥有 IMA 凭证、编码和 notes 工具调用约束。
- 固定目标笔记、同日去重和 notes API 追加后缀日期段时的契约保持不变。

## 输出契约

首次输出是“处理结果”，必须在任何 IMA 工具调用前发送；最终输出是“处理与保存结果”，必须来自真实调用结果。两次输出中的标准信息必须一致，除非 IMA 返回仅影响保存状态的错误；保存过程不得改写标准信息。

## 失败处理

- 信息处理失败：输出待确认信息，IMA 状态为未执行，不进入保存阶段。
- IMA 前置验证、读取或写入失败：保留真实错误，最终输出保存失败。
- 当天内容全部重复：不调用写入接口，最终输出跳过重复内容。
- 当天已有内容且存在新增事务：使用递增后缀追加 `## YYYY-MM-DD (N)` 日期段，最终输出追加成功。

## 验证场景

1. 有效单日日志：首次输出出现在 IMA 调用前，随后自动保存并输出成功结果。
2. IMA 不可用：首次标准信息仍先输出，最终准确输出保存失败。
3. 日期缺失：只输出待确认结果，不调用 IMA。
4. 内容重复：首次标准信息先输出，最终输出跳过重复内容且不写入。
5. 同日新增内容：首次标准信息先输出，最终输出追加成功，日期段为 `YYYY-MM-DD (N)`。

## 非目标

- 不增加人工确认步骤。
- 不改变标准信息的语言、格式或事实约束。
- 不改变目标笔记和 IMA 去重语义。
- 不新增通用工作流框架或兼容分支。
