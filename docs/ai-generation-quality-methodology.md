# 可控与不可控：AI 生成任务的质量工程方法论

> 适用：任何以"AI 模型产出物"为交付的 skill（视频 / 图片 / 文案 / 代码 / 设计稿……）。
> 一句话核心：**流程和 model 是"设计出来的"，创意是"让出来的"，质量是"逼近出来的"。**
> 任何声称"保证高质量"的生成系统都在骗人——质量不是一次写成，是靠闭环迭代逼近的。

---

## 0. 先给结论：为什么"质量"这么难

你本能地会想把 skill 拆成若干模块去设计。但当你拆到"质量"这一格时，你会发现它**没法直接设计**——这不是你的失败，是质量的性质决定的：

- 你能设计**输入**（流程、建模、拼装、约束）。
- 你不能直接设计**输出质量**，你只能去**验**输出，然后**逼近**。

这篇文章把"怎么面对这个不可控"拆成可执行的机制，答完三个问题：
1. 我控制不了的东西，怎么分类对待？（§1 可控性光谱）
2. 质量到底是什么、分几层、每层怎么保证？（§2-§3 质量的叠）
3. 怎么把"该带哪把锁"从"模板巧合"变成"规则必然"？（§4-§7 闭环）

---

## 1. 可控性光谱：先分清四类性质的工件

把所有工件按"工程到底能控制到什么程度"排成一条光谱：

| 类别 | 可控性 | 对待方式 | 反面做法 |
| --- | --- | --- | --- |
| **流程** | 100% 可控 | **值得好好设计**：路由、步骤、铁律 | 不设计，放任自由发挥 |
| **model（建模）** | 可控且稳定 | **定好 schema 即可**：维度 + 必填 + 变体轴 | 反复折腾、过度扩展 |
| **创意** | 脚手架可控，爆发不可控 | **只提供"让 AI 发挥的容器"**：骨架/模板/钩子 | 把创意写成死模板 |
| **质量** | 只有"降险 + 验证"可控，"达成"不可控 | **只能逼近**：降险 + 验 + 迭代 | 妄图一步到位 |

**关键区分**：前三格回答的是"你能控制什么"，质量回答的是"你如何应对你控制不了的东西"。质量跟另外三格**不是同一类问题**——这就是它"最难"的根因，也是它不是第 4 类、而是一叠的原因。

> 判定一个问题归哪一格的简单问法："靠把文档写得更细，能直接提升它吗？"
> 能 → 流程或 model；只能靠换模型/多次生成 → 创意或质量。

---

## 2. 质量的本质：不是一格，是一叠

质量不是决策链里的一个独立模块，而是**整条决策链跑完一遍后的涌现结果**：

```
质量 = f(建模完备度 × 流程结构 × 创意表达 × 拼装手艺)
```

它由多个层叠成，每层的保证机制完全不同。所以"怎么才算高质量"没有单数答案，只有分层的诚实答案：

- **能判定的** → 做成**判定标准**（客观校验 + 结构化人工审）。
- **不能判定的** → 做成**迭代协议**（逼近流程，不假装一次达成）。
- **把边界说清楚** → 不声称"保证质量"，只声称"降险 + 逼近"。

> 这句是整篇的灵魂：**能判定的做成判定标准，不能判定的做成迭代协议。**

---

## 3. 质量五层：每层的保证机制完全不同

| 层 | 是什么 | 保证机制 | 可控性 |
| --- | --- | --- | --- |
| **L1 客观参数** | 时长 / 宽高 / 帧率 / 体积 | probe 等客观校验，可机器判定 | 可判定 |
| **L2 一致性 / 常理** | 主体 / 场景 / 风格不漂移；解剖 / 重力 / 遮挡正确 | 源头"锁" + 抽帧人工审 | 可判定 |
| **L3 防崩坏** | 变形 / 穿模 / 乱码 / 抖动 | 正向常理锁 + 反模式清单 | 可判定 |
| **L4 审美** | 调色 / 构图 / 质感 / 光比 | 风格锚 + 美学母体 + 参考图 | 半可控、主观 |
| **L5 情绪 / 传播力** | 钩子 / 节奏 / 感染力 | 骨架脚手架 + 模型能力 + 人 | 不可控 |

**推论**：L1-L3 今天就能做成判定标准；L4 用"锚 + 参考"尽量收窄主观空间；L5 只能靠脚手架 + 迭代逼近。**任何把 L4-L5 当 L1 来"保证"的做法都在自欺。**

---

## 4. 关键机制：质量锁要"推导"，不要"模板巧合"

这是最容易踩的坑，也是让一个 skill 从"看起来专业"变成"真能控质量"的分水岭。

**误区**：在模板里写死几条 `Hard constraints`（stable frame / natural anatomy / no mutation），就以为做了质量。
**真相**：这些锁是**写死的**，不是**推导出来的**。模板"恰好"带了这条锁 ≠ 规则"必然"推导出这条锁。

质量 = **具体情境下该带哪把锁** + **生成了怎么验**。而"该带哪把锁"不由模板决定，由**本次的建模/路由决策**决定：

| 本次决策 | 必须推导出的锁 | 防什么 |
| --- | --- | --- |
| 走了 i2v（锚定生成） | 身份锁 `keep identity consistent` | 主体换脸 / 变形 |
| 多镜 / 多段 | 主体锁 + 场景锁 + 跨段锁 | 中段漂移 |
| 含字幕直出 | `no wrong text` + 引号包数字 | 乱码 / 错字 |
| 治愈 / 慢节奏 | `stable frame` + `no shaky-cam` | 抖动毁情绪 |
| 转化 / 带货 | 数字引号 + 品牌名逐字 | 关键信息错字 |
| 高动态 / 快节奏 | `no mutation` + 重力锁 | 崩坏 |

**落地方式**：把这张"决策 → 锁"映射表做成质量层的**推导源**；拼装层加一个**必选子步骤**——"按本次路由选锁 + 写一句为什么"。让选锁成为推导结果，而不是模板巧合。

> 判断是否做对了：把"这次为什么带这把锁"问 AI，它能从决策链答出来，而不是因为模板里恰好有。

---

## 5. 质量闭环：不是清单，是闭环

质量靠迭代逼近，所以它的组织形态是**闭环**，不是一份一次性清单：

```
上游：质量锁推导（按建模决策 → 自动决定带哪几把锁）→ 焊进拼接层
   ↓
中游：质检门（客观校验 + 抽帧人工审）
   ↓
下游：局部重生成 / 后期增强
   ↓（不达标 → 修锁重拼，回到上游）
贯穿：迭代协议（一次写不成，逼近出来）
```

- **上游**：把质量知识变成"推导源"，而不是散落的验证条款。
- **中游**：客观 + 结构化人工审，给出"接受 / 局部重做 / 整体重做"的判定。
- **下游**：局部重生成（只重做错段）+ 后期增强（见 §6）。
- **贯穿**：迭代协议决定"下一轮改哪里"（见 §7）。

---

## 6. 后期 = 杠杆，不是兜底

很多设计把"后期处理"当**降级兜底**（模型直出不了才做）。方向对，但丢了一半价值。

后期有两种角色，应该分开设计：

| 角色 | 触发 | 目的 |
| --- | --- | --- |
| **兜底** | 模型直出错（乱码 / 没对上） | 修正到可交付 |
| **增强** | 直出成功但可更好 | 从 80 分推到 90 分（调色 / 字幕设计 / BGM 卡点 / 节奏） |

所以"直出 / 后期"决策表应该是**三态**，不是二元：

```
直出（默认）→ 增强（可选，加分项）→ 兜底（出错才降级）
```

---

## 7. 迭代协议 = 不可控部分的唯一可控面

L4-L5 不可控，但"逼近的过程"本身**可以被设计**。这是你对不可控做出的唯一可控杠杆。

设计迭代协议时，至少要回答三个交互决策：

1. **决策点**：哪些节点需要问用户（分段 / 路径 / 降级 / 增强）？不问会默认成什么？
2. **失败呈现**：失败/不达标怎么呈现？给用户"重做哪一段"的指引，而不是笼统的"重来"。
3. **下一轮输入**：上一次质检的结论，怎么变成下一轮的 prompt 修正（修哪把锁、改哪段）？

> 迭代的体验决定了质量能逼近到什么程度。**闭环能不能收敛，取决于协议设计，不取决于模型**。

---

## 8. 迁移清单：怎么把方法论用到别的 skill

把一个生成类 skill 套进这套方法论，按顺序过一遍：

- [ ] **① 画可控性光谱**：把工件分成 流程 / model / 创意 / 质量 四类，别把四类混为一谈。
- [ ] **② 只深度设计流程和 model**：流程值得折腾，model 定好 schema 就别反复改。
- [ ] **③ 创意只给容器**：骨架/模板/钩子给出"让 AI 发挥"的边界，不写成死板模板。
- [ ] **④ 质量按层拆**：能判定的（L1-L3）做成判定标准，不能判定的（L4-L5）做成迭代协议。
- [ ] **⑤ 建"决策 → 锁"推导表**：让拼装时"该带哪把锁"是推导结果，不是模板巧合。
- [ ] **⑥ 组织成闭环**：锁推导 → 质检门 → 增强/重生成 → 迭代，而不是一次性清单。
- [ ] **⑦ 后期三态**：兜底 / 增强分开，别把增强当成降级。
- [ ] **⑧ 把迭代协议当产品设计**：决策点、失败呈现、下一轮输入，都值得好好设计。
