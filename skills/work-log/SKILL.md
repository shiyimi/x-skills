# 工作日志流程

将流水账处理为两部分标准信息：先输出事项汇总清单和事项明细，再自动保存到 IMA，并按固定模板展示处理与保存结果。

必须严格按以下顺序执行：

`信息处理 → 立即展示标准信息 → 自动保存到 IMA → 展示保存结果`

## 阶段一：信息处理

1. 确认日志日期。日期优先取自用户输入或明确上下文，并统一为 `YYYY-MM-DD`；日期缺失或存在歧义时默认使用当前日期，不再额外询问。
2. 读取并严格执行 `references/information-processing.md`，将原始记录处理为标准信息。
3. 记录处理结果：
   - 能同时形成事项汇总清单和事项明细：`处理状态 = 已完成日志处理`。
   - 日期无法确认或原始信息不足：`处理状态 = 未完成日志处理`，不得进入保存阶段。

## 阶段二：标准信息立即展示

标准信息处理完成后，必须先立即输出以下处理结果，供用户填写部门日志；此阶段不得调用 IMA，也不得等待用户确认：

```Markdown
【处理结果】
完成状态：已完成日志处理
当前日期：## ${YYYY-MM-DD}
处理模式：${日志新增 | 日志合并去重 | 待保存}

【事项汇总清单】
${事项汇总清单}

【事项明细】
${事项明细}
```

信息处理未完成时，输出待确认结果并停止，不进入 IMA 保存阶段。

## 阶段三：标准信息保存

首次处理结果输出完成后，不等待用户确认，立即使用 `ima-skill` 的 notes 模块尝试保存。

目标笔记：

- 名称：`个人工作日志`
- `note_id`：`7480155970751316`

保存流程：

1. 验证 IMA 凭证、API 可达性、notes 权限和运行依赖。
2. 验证失败时允许继续流程，但必须记录真实失败原因，设置 `保存状态 = 保存失败`，停止 IMA 读取和写入，然后进入标准信息展示。
3. 验证成功后，使用 `get_doc_content` 读取目标笔记完整正文。固定 `note_id` 无效、无权限或已删除时记录真实错误并进入展示；不得创建同名笔记替代固定目标。
4. 使用独占行 `## YYYY-MM-DD` 定位当天日志，只在同一日期内去重，不得跨日期比较。
5. 事项明细是唯一去重事实源。以事项明细中的每个编号条目为最小去重单元，编号本身不参与语义比较：
   - 动作、对象、进展和结论语义一致：跳过。
   - 包含新增事实或进展变化：保留。
   - 事项汇总清单不独立参与去重；完成明细去重后，只为保留的新增明细生成对应汇总项。
6. 当天日期不存在时，使用 `append_doc` 追加以下 Markdown：

````markdown
## YYYY-MM-DD

### 事项汇总清单

${事项汇总清单}

### 事项明细

```text
${事项明细}
```
````

7. 当天内容全部重复时，逐事务对比 `## YYYY-MM-DD` 及其所有后缀日期段 `## YYYY-MM-DD (N)` 下的内容。全部重复时不调用写入接口，设置 `保存状态 = 跳过重复内容`。
8. 当天日期已存在且有新增事务时，使用递增后缀编号追加新日期段：
   - 检查笔记中已存在的后缀日期段 `## YYYY-MM-DD (2)`、`## YYYY-MM-DD (3)` 等，找到最小可用后缀编号（从 2 开始递增）。
   - 使用 `append_doc` 在笔记末尾追加以下 Markdown：

   ````markdown
   ## YYYY-MM-DD (N)

   ### 事项汇总清单

   ${新增事项汇总清单}

   ### 事项明细

   ```text
   ${新增事项明细}
   ```
   ````

   - 设置 `保存状态 = 保存成功`，`处理模式 = 日志新增(追加)`。
9. API、网络、权限、版本或编码错误均允许保存失败，但必须保留真实错误。写入前遵守 `ima-skill` 的 UTF-8 规则。
10. 保存成功时记录 API 返回的 `note_id`；保存失败时不得声称已保存。

## 阶段四：保存结果展示

IMA 尝试完成后必须执行本阶段。信息处理未完成时不进入本阶段。只输出以下模板，不在模板前后添加额外说明：

```Markdown
【处理结果】
完成状态：${已完成日志处理 | 未完成日志处理}
当前日期：## ${YYYY-MM-DD | 待确认}
处理模式：${日志新增 | 日志新增(追加) | 未进入保存}

【IMA 保存结果】
保存状态：${保存成功 | 保存失败 | 跳过重复内容 | 未执行保存}
目标笔记：个人工作日志
失败原因：${无 | IMA真实错误 | 未执行保存原因}

【事项汇总清单】
${事项汇总清单 | 待确认}

【事项明细】
${事项明细 | 待确认}
```

字段规则：

- `完成状态` 只表示信息处理结果，不代表 IMA 保存结果。
- `处理模式`：当天日期不存在为 `日志新增`；当天日期已存在且有新增事务为 `日志新增(追加)`；未完成信息处理或未能读取 IMA 时为 `未进入保存`。
- `保存状态` 必须来自真实执行结果。
- 没有失败时，`失败原因` 固定为 `无`。
- IMA 连接或保存失败时仍展示已经生成的事项汇总清单和事项明细。
- 两部分必须基于同一组有效事务，同时生成、同时展示、同时保存。
- `事项汇总清单` 采用连续文本，每项固定为 `【项目/系统/模块/功能】核心事项；`，不得使用列表或换行。
- `事项明细` 采用数字编号分条列举；交互展示时直接输出，保存到 IMA 时放入 `text` 代码块。
- 两部分不得混入保存过程、错误说明或额外标题。
