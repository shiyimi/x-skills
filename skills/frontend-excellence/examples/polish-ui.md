# 示例：界面打磨

## 用户请求示例

“这个页面功能差不多了，但看起来太普通，帮我打磨到更专业一些。”

## 主任务模式

UI / 交互打磨

## 建议优先读取

- 必读入口：`references/00-core-principles.md`、`references/01-quality-gates.md`、`references/03-simplification-discipline.md`
- `references/13-accessibility-interaction.md`
- `references/14-styling-visual-quality.md`
- `references/15-testing-verification-rollbacks.md`
- 主模式不清或任务混有重构 / 实现时：`references/02-task-routing.md`
- 如果结构影响成品感：`references/10-component-architecture.md`

## 应重点关注

- 信息层级是否清楚
- 布局和留白是否服务内容结构
- 交互反馈是否成熟
- 响应式和可访问性是否仍然成立
- 是否避免了平庸模板感和无意图装饰

## 推荐输出骨架

1. 先明确视觉方向或风格原型，以及不该像什么
2. 再说明信息层级、阅读路径和页面记忆点
3. 再交代交互反馈、响应式和可访问性如何成立
4. 若结构问题会拖垮成品感，先把这些前置条件说清楚
