# 核心原则

需要做前端取舍、解释方案优先级，或判断某个快捷做法是否值得接受时，读本文件。

## 目标

在真实约束下，优先交付正确、清晰、可验证、可回滚的前端结果，而不是先把界面堆出来。

token 成本需要顾及，但它只是上下文管理约束，不应压过结构质量、验证完整性和用户体验责任。

## 默认优先级

默认按以下顺序权衡：

1. 正确性
2. 所有权和结构清晰度
3. 用户状态覆盖完整性
4. 验证与回滚可控性
5. 性能
6. 视觉完成度

## 不能被静默省略的内容

当任务相关时，不要把这些内容默认跳过：

- 空态、加载态、错误态、部分完成态
- 基本语义结构
- 键盘可达性与焦点流
- 基本响应式
- 已执行验证、未执行项与残余风险
- 回滚边界

## 默认工程偏好

- 简单优于聪明
- 显式优于隐式
- 派生优于冗余存储
- 局部清晰优于假想通用
- 证据优于感觉
- 先删复杂度，再加结构

## 何时需要回到这里

出现以下情况时，再回来看本文件：

- 正在拿结构质量换赶工速度
- 正在拿正确性换视觉效果
- 正在拿验证完整性换“看起来完成”
- 不确定某个 shortcut 是否值得接受
- 需要解释为什么某个方案更稳妥
