# 测试、验证与回滚

在前端任务完成前后判断验证策略、真实性表达、残余风险和回滚边界时读取本文件。

## 最小验证组合

- 实现：主路径、关键用户状态、类型 / 语法、至少一个关键交互
- 重构：行为保持点、旧路径删除条件、回滚边界、关键回归点
- 评审：证据范围、未验证项、严重度排序，而不是只给结论
- 调试：现象、证据、假设分开；至少一个验证动作或下一步验证顺序
- 性能优化：基线症状 / 指标、优化后观察点、潜在回归点
- UI / 交互打磨：桌面端、移动端、焦点 / 键盘 / 反馈中的至少相关项

## 何时本地检查不够

- 焦点流、键盘路径、拖拽、滚动、动画、溢出
- hydration 闪烁、主题切换、路由抖动、客户端 / 服务端边界问题
- 图片、字体、脚本、接口延迟在真实环境中的加载差异
- 只在 preview / staging / production 才稳定出现的问题

## 至少要确认什么

- 主路径是否可用
- 空态、加载态、错误态、部分完成态是否成立
- 关键交互是否有反馈
- 关键边界是否没有明显破坏
- 主要设备或布局场景是否没有立即崩坏

## 未执行项与真实性

未执行项必须明确写出；不要把推断写成已验证结论。

- 没跑测试
- 没做类型检查
- 没做真实浏览器验证
- 没验证移动端
- 没验证异常路径

## 回滚边界

- 这次改动影响哪些文件、组件或流程
- 哪个点最适合作为回滚边界
- 是整体回滚还是局部回滚
- 哪些新增路径可单独撤回

## 输出义务

- 实际执行了哪些验证
- 哪些验证没有做
- 为什么没做
- 还有哪些风险
- 回滚边界在哪里
