# 样式与视觉质量

在处理布局、层级、响应式、界面完成度和交互质感时读取本文件。

如果视觉表达和结构清晰度冲突，先修结构，再谈样式。

## 先回答这四问

- 用户最先该看哪里
- 当前主要操作是什么
- 页面想传达什么气质
- 它最不该看起来像哪种默认模板

## 默认目标

- 信息层级清楚
- 视觉节奏稳定
- 布局与内容结构一致
- 桌面端和移动端都成立
- 反馈自然，风格有意图

## 风格原型

- `Editorial`：强标题、明确留白、章节节奏
- `Calm Enterprise`：稳定层级、克制对比、可信反馈
- `Technical Instrument`：明确栅格、数据主次、局部高对比
- `Premium Ops`：精准字重、干净块面、节制强调色

## 层级工具

- 字号与字重
- 间距与分组
- 色彩对比
- 对齐与留白
- 背景层次与阅读路径

## 打磨顺序

1. 先选视觉方向和不该像什么
2. 再理顺信息层级和阅读路径
3. 再决定块面、背景、强调色和字重节奏
4. 最后才补动效、装饰和局部质感

## 避免默认安全选择

- 白底 + 浅灰边框 + 随手圆角的通用后台感
- 所有区块长得一模一样
- 只靠卡片堆叠制造层次
- 无意图的渐变、阴影、圆角堆叠
- 只靠颜色变化营造“高级感”

## 响应式与交互

- 小屏下关键操作仍可达
- 溢出、换行、截断策略清楚
- 重排后层级仍成立
- hover / active / focus / loading / error 表达一致

## 先查结构问题

- 信息模型混乱
- 组件边界不清
- 状态表达混乱
- 交互优先级错误

## 输出义务

- 主要提升了哪一层视觉质量
- 选择了什么视觉方向，以及为什么
- 信息层级如何被理顺
- 记忆点或辨识度来自哪里
- 响应式和交互反馈如何被考虑
