## 阶段 A · 路由与判定

## §0 图片路由(第一屏)

按 brief 关键词匹配骨架与默认路径。命中后直接推进,不反向引用 SKILL。

| brief 关键词 | 骨架 | 默认路径 | 关键点(默认配置) |
| --- | --- | --- | --- |
| 产品图/白底图/商品图(无实拍) | A 主体居中 | G | 中近景 + 顶光 5000K + 浅色背景 |
| 产品图(有实拍) | A 主体居中 | E(i2i) | 仅改背景/光影,列保留项(主体/材质/品牌) |
| 海报/封面/推广 | B 分区拼贴 | G/H | 分区 + 多字体 + 角标([I3 §1.3](I3-prompt.md)) |
| 人像/穿搭/lookbook | C 人物构图 | G/E | 1/3 构图 + 自然光;有人像实拍→强 i2v |
| 美食/ASMR | A 主体居中 | G | 微距 + 顶光 4500K |
| 概念图/插画/氛围 | D 场景叙事 | G | 广角 + 黄金时刻光,加 1-2 动态元素 |
| 风景/氛围 | D 场景叙事 | G | 广角 + 黄金时刻光,避免空盒子感 |
| 标识/icon/logo | E 极简符号 | G | 极简 + 主色 60%+,锁品牌色逐字 |
| **商业带货** | A/B | **E 优先(i2i)** | [../recipes/commerce.md §2](../recipes/commerce.md) 品类配置 + R5 + [合规清单 §8](../recipes/commerce.md) |

> **匹配规则**:命中多个 → 取最强信号(如"产品海报"优先 B)。**匹配失败**(关键词未命中/能力缺口) → 如实报告能力缺口 + 降级为纯 brief 直出。

## 铁律(R1-R5,图片专属)

R1-R5 是视频铁律(R1-R7)的**单帧降维版**。R2/R3/R5 直接沿用;R1/R4 重写。图片不使用视频 R1-R7。

| # | 铁律 | 含义 |
| --- | --- | --- |
| R1 | 一次定路径,坚持到底 | 尽早选择路线(t2i/i2i/多图拼贴),prompt 中途不切换 |
| R2 | 视觉驱动,而非罗列要点 | 1 张图 ≤ 1-3 个视觉重点(★) |
| R3 | 图层纪律 | 前景/中景/背景各有可命名元素 + 1 光源;文字层锁定字体/色板/位置/描边 |
| R4 | 1 秒内首眼钩子 | 首屏视觉冲击在前 1/3 画面 |
| R5 | 零错字,品牌名逐字照搬 | 大小写·空格·标点全部照搬 |

> **图片专属**:图片不使用视频 R1-R7,视频铁律见 [C1-flow.md](../library/C1-flow.md)。落点由各小节声明,铁律表本身不内联路径。

## §1 路径判定(决策一次,后续不切换)

**铁律 R1(见上表)**:t2i/i2i/多图拼贴,决策一次,后续不切换——生→改→生 = 漂移 + 成本翻倍。

| 判定问题 | 是 → 路径 | 否 → 路径 |
| --- | --- | --- |
| Q1. 有**实拍参考图**且需**保留主体/构图**? | **E 二次编辑** — i2i 或分区替换 | 进入 Q2 |
| Q2. 需**从头生成新图**? | **G 纯生成** — 完整 prompt → Provider | — |

| 路径 | 触发 | 保真度 | 动作 |
| --- | --- | --- | --- |
| **G 纯生成(t2i)** | 无参考图/从 0 设计 | 取决于 prompt 锁定 | §5 规范表 + [I3 §2](I3-prompt.md) prompt → Provider |
| **E 二次编辑(i2i)** | 有实拍参考图,需保留主体 | 与原图完全一致 | `保持<保留项>,把<修改项>替换为<新内容>`([I3 §2.2](I3-prompt.md)) |
| **H 多图分区** | 海报/拼贴(多图层多区域) | 每区域独立 | [I3 §1.3](I3-prompt.md) 分区边界 + [I3 §2.2](I3-prompt.md) H 路径 |

### 1.1 路径结果写入 image-brief 表头

Brief header 必填一行 `生成路径`:

```
生成路径: G (纯生成)  |  E (二次编辑)  |  H (多图分区拼贴)
```

## §3 内容创作 · 写提示词(需求 → 内容提示词)

### 3.1 需求解构(先解析为三槽位)

把 brief 解析为三个槽位,缺位用既定默认值填(文档表头标 `默认假设`):

| 槽位 | 必填字段 | 缺位默认 |
| --- | --- | --- |
| 主题/产品 | subject, 1-3 个视觉重点/卖点, 素材(参考图/品牌色) | 来自 request; 真缺失就 1 轮追问 |
| 人群/受众 | 目标用户,使用场景 | 通用 9:16 信息流素材 |
| 目标 | 认知(品牌)/ 兴趣(种草)/ 转化(带货)/ 实用(教程/标识) | 按 request 判断 |

### 3.2 内容提示词(需求 → 自由文本)

> **位置**:套骨架之前。先把用户需求写成**内容提示词**(一段自由文本,一句话说清这张图画什么/表达什么),作为规范表与 Final Prompt 的唯一源头;骨架只定"怎么构图/怎么排版",**不重写"画什么"**。需求是片段的(只有一个主体/一个画面),补成完整内容;需求自带构图(品牌海报/实拍参考),提炼主体与重点,不重写。

| 要素 | 定义 | 示例(蓝牙耳机产品图) |
| --- | --- | --- |
| 主体 | 画什么,≥3 特征 + 材质/状态 | 哑光黑色蓝牙耳机,金属铰链,USB-C 充电口 |
| 场景 | 在哪儿,前/中/背景三层 + 光源 | 浅米背景+侧窗光,桌面+绿叶点缀 |
| 视觉重点 | 1-3 个(★),要突出什么 | 主体质感 + 极简高级感 |
| 基调 | 风格/情绪/光影基调 | Apple 极简产品摄影,中低饱和冷调 |

**产出**:`<name>.image-brief.md` 的 `提示词` 区块,一段 3-5 句自由文本 + `负面提示词` 区块(3-5 项"不要什么",题材/画面层,写 Prompt 时并入约束块 `no X`,§7)。

> **image-brief 完整结构**(后续步骤补全,最终四段):
> 1. **图片主要目标**: `产品/主题 × 人群 × 目标 × 视觉骨架(§4) × 画幅([I3-prompt.md §2.3](I3-prompt.md)) × 用途`
> 2. **提示词(创作内容)**: 独立区块,主体/场景/视觉重点/基调(§3) + `负面提示词`(3-5 项,并入约束块 `no X`,§7)
> 3. **视觉规范表**: 一行或多行,§5;表头锁定 `默认假设` / `美学母体` / `文字策略` / `生成路径`
> 4. **图片 prompt**: 一段完整 prompt,按 [I3-prompt.md](I3-prompt.md) §2 拼装 + §3 约束块收尾(§7)

**自检**:
1. 内容提示词完整吗?主体/场景/视觉重点/基调四要素都有?
2. 骨架没重写内容吗?骨架只负责构图与密度(§4),不换"画什么"
3. 内容能驱动规范表吗?每个要点都能映射到规范表字段(§5)
4. 负面提示词列了吗?题材/画面层 3-5 项"不要什么"(如无错字/无水印/无文字被裁切)已写入 brief

## §4 视觉骨架与 ★ 密度(Step 3)

骨架速选(信号词 → 骨架)已并入 §0 路由;本节定义各骨架的构成与质量细节。

| 骨架 | 元素数 | 文字层 | 用途 |
| --- | --- | --- | --- |
| A 主体居中 | 1 主体 + 3+1 道具 | 无或 ≤1 | 电商/产品详情/广告 |
| B 分区拼贴 | 1-2 主体 + 多区域 | 1-3 层 | 品牌/活动/社媒 |
| C 人物构图 | 1 人物 + 场景 | 无或 ≤1 | 时尚/形象/社交 |
| D 场景叙事 | 1-2 主体 + 场景 | 无 | 故事/治愈/概念 |
| E 极简符号 | 1 主体 | 1 层(品牌名) | 品牌/UI/水印 |

### 4.1 视觉重点 ★ 密度

| 骨架 | ★ 数 | 分布 | 自检 |
| --- | --- | --- | --- |
| A 主体居中 | 1 ★(主体) | 中心 50% | 一眼看清? |
| B 分区拼贴 | 1-2 ★(主标题区 + 主体区) | 上下或左右各 1 | 扫一眼抓重点? |
| C 人物构图 | 1 ★(人物) | 1/3 构图点 | 有故事感? |
| D 场景叙事 | 1-2 ★(主体 + 氛围锚) | 1 主体 + 1 锚点 | 一秒入戏? |
| E 极简符号 | 1 ★(符号本体) | 中心 | 高识别度? |

### 4.2 R4 · 首眼钩子

| 钩子类型 | 范式 | 适合 |
| --- | --- | --- |
| **对比钩** | 强对比(冷暖/明暗/大小)在前 1/3 画面 | A 产品图 / B 海报 |
| **构图钩** | 1/3 构图点 + 引导线 | C 人物 / D 场景 |
| **色彩钩** | 主色占画面 60%+,极端色环位置 | B 海报 / E 符号 |

> **自检**:缩到 200x200,眯眼扫 1s,能立刻看到主体?

## §5 视觉规范表(Step 4)

### 5.0 单行模板

| 字段 | 规则 | 示例(产品图) |
| --- | --- | --- |
| 区域 ID | `Z01`(分区时用 Z01/Z02/...) | Z01 |
| 用途 | 该区域功能 | 产品主体 |
| 主体 | ≥3 特征 + 材质/状态 | 哑光黑色蓝牙耳机,充电盒,金属铰链 |
| 景别与视角 | 景别 + 机位 + 构图 | 中近景,平视,中心构图 |
| 光影 | 方向 + 色温 + 光比 + 光质 | 顶光 45°,5000K,光比 2:1,柔光 |
| 色彩 | 主色 + 辅色 + 色调 | 哑光黑+冷灰,中低饱和冷调 |
| 前景/中景/背景 | 3+1 规则(可命名道具 + 光源) | 前景:耳机/中景:充电盒/背景:米白窗帘虚化 |
| 文字层 | [I3-prompt.md §1.1](I3-prompt.md)(无文字则 —) | 主标题"BlackBeats X1"中下,黑字白边 |
| 视觉重点 | ★ = 封面级 | ★ |
| 视觉重点 2 | 二级 ★(可选) | — |
| 风格 | 摄影类型 + 美学基调 + 负向 | 产品摄影,Apple 极简 |

> 颗粒度标尺(抽象 vs 具体)见 [I2-quality.md §1](I2-quality.md)。

## §6 规划自检(提交生成前)

> 规划层自检;prompt 层对照(反模式)见 [I2-quality.md §2](I2-quality.md),成片后见 §9 质检门。

```
1. 路径决策:路径 G/E/H 已定,表头锁定(§1)
2. 内容提示词:主体/场景/视觉重点/基调四要素齐全,骨架未重写内容(§3)
3. 骨架已选:与 brief 目标匹配,★ 密度达标(§4.1)
4. 视觉规范表 11 列都填了?分区图多行(§5)
5. 场景 3+1 + 光源写全,无空盒子(§5)
6. R5 铁律:品牌名/型号/成分/数字引号 + verbatim(§7)
7. 首屏 1 秒钩子:缩到 200x200,眯眼扫 1s 能看到主体?(§4.2)
```

## 阶段 C · 产出(Step 5-6)

## §7 写 Prompt(Step 5)

把规范表(§5)落成可直接提交的图片 prompt:

- **模板 + 规则**:拼 prompt 用 [I3-prompt.md](I3-prompt.md)(七维度/拼装顺序/画幅) + [I2-quality.md](I2-quality.md)(颗粒度/反模式)。
- **层分离**:规范表展示层的技术参数(色温 K/焦段/角度)语义化后写入执行层;**剧情爆点数字(金额/名称/年龄)必须原样写进 prompt**。
- **直接中文**:final prompt 用自然中文重述"画面长什么样",不堆数字、不英文换算(见 [I3-prompt.md §4](I3-prompt.md))。
- **R5 零错字**:品牌名/型号/成分/数字用引号包裹 + `按引号内文字原样渲染`,末尾加安全边距([I3 §1.2](I3-prompt.md) / [I3 §1.4](I3-prompt.md))。
- **约束块收尾**:每个 prompt 以 [I3 §3.1](I3-prompt.md) 约束块收尾;内容创作产出的 `负面提示词`(§3,题材/画面层)以 `no X` 并入约束块([I3 §3.2](I3-prompt.md));不独立维护 negative_prompt。
- **系列一致性**:系列图按 [I2 §3](I2-quality.md) 锁主体描述符 + 美学母体,每张只换 ≤3 个变量。

## §8 生成与提交(Step 6)

将 image-brief 提交给媒体 Provider 产出图片(能力 `text-to-image`(G) / `image-to-image`(E/H),契约见 [core/provider-contract.md](../../core/provider-contract.md)):

- **编排入口**:`core/orchestrator.cjs`。CLI `submit <name>.image-brief.md`/`status`/`download` 与视频共用同一编排链路;submit 按文件后缀识别 `.image-brief.md` → 图片能力(`text-to-image`(G) / `image-to-image`(E/H)),固定任务同样记入 `.y-media/tasks.json`,凭 task_id 查询或取回。能力缺口仍如实报告,不静默降级。
- **E/H 路径**:需在 brief 表头 `默认假设` 提供参考图 HTTPS URL;元素级绑定写法见 [I3 §2.2](I3-prompt.md)。

## 阶段 D · 验证与交付(Step 7)

## §9 质检门(验证图片)

下载后跑一遍客观校验 + 人工审,决定接受/重生成。**非量化质量因素与反模式对照见 [I2-quality.md](I2-quality.md)**:

| 检查 | 方法 | 不达标时 |
| --- | --- | --- |
| 尺寸/画幅/格式 | 客观校验 | 参数不符 → 重生成 |
| 文件完整性 | 存在 + 大小 > 0 + 是图片格式 | 异常 → 重提任务 |
| 视觉重点 ★ | 缩到 200x200,眯眼扫 1s 能看到主体? | 不清晰 → 修规范表重生成 |
| 反模式(I3 §2) | 逐项对照:多主体/空盒子/文字错字/i2i 漂移/系列漂移 | 命中 → 按 §10 修复 |
| 文字零错字(R5) | 品牌/型号/成分/数字逐字核对 | 错字 → 只重生成该图 |

> 能力缺口不伪造:本机缺依赖时如实报告并给降级路径,不从文件名/默认值推断。

## §10 失败呈现与迭代引导

> 结果不达标时,**如实呈现失败原因 + 给一条可执行的修复路径**,不静默重试、不伪造产物。

| 失败/打回 | 呈现 | 引导 |
| --- | --- | --- |
| 生成任务失败(Provider/task 错误) | 报告 Provider 报错原文 + 任务 id | 重提任务,或切 Provider 重试 |
| 客观参数不符(尺寸/画幅) | 报实测值 vs 目标值 | 修参数重生成 |
| 多主体/抽象堆砌/空盒子 | 报反模式命中项([I2 §2](I2-quality.md)) | 回 §5 规范表补具体字段,重拼 prompt |
| 文字错字/乱码 | 报错字证据 | 只重生成该图;R5 引号 + verbatim(§7) |
| i2i 漂移/系列图漂移 | 报漂移证据 | 回 [I2 §3](I2-quality.md) 补主体描述符/美学母体锁 |
| 能力缺口(缺工具/依赖) | 如实报告缺口 + 最小前置 | 给补齐命令或降级路径,不推断 |

> **同类原因第二次出现** → 不是运气问题,是规则缺口:回写 I2/I3 把这次教训固化成规则,下一轮直接命中。

## §11 交付硬约束(可预览 + 可下载)

每次工作流结束,**所有产出文档与最终产物必须以「可预览 + 可下载」双通道呈现**,禁止只给本地路径或纯文本描述:

| 交付物 | 可预览 | 可下载 |
| --- | --- | --- |
| 图片产物 | 内联嵌入 `![图片](相对路径.png)` + 显式预览链接 `[预览](相对路径.png)` | 附文件下载链接(相对路径) `[下载](相对路径.png)` |
| `<name>.image-brief.md` | 显式预览链接 `[文档](相对路径.md)` | 附文件下载链接(相对路径) `[下载](相对路径.md)` |

> **硬约束**:交付结论中每项都同时给出**可点击的预览链接** + 可下载链接;缺任一通道即为未完成交付。**预览与下载链接一律用相对路径**(相对当前交付文档所在目录),禁止 `file://` 绝对路径或含盘符的全路径——绝对路径无法内联预览且跨环境失效。
