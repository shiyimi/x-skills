# C2. quality · 非量化质量与写作规则(质检·防崩坏·后期·写脚本)

> 本文件是**贯穿全流程的质量总纲**(core)+ **Step 5 写脚本的写作规则**。客观校验(时长/宽高/帧率)只能拦参数错误,拦不住"看起来假"——本篇管理**不能量化**的质量因素,以及"怎么写对"的规则(动作/镜头/字幕/音频/质量锁/自检)。
>
> **分工**:各建模文件(M1-M5)的 schema 表负责"该填什么"(M1 角色 / M2 场景 / M3 镜头 / M4 音频 / M5 字幕);[C3-prompt-craft.md](C3-prompt-craft.md) 管"模板长什么样";本篇管"**怎么不翻车 + 怎么写对 + 怎么验证**"。
>
> **源头写对**:质量在规划与 prompt 阶段就锁死,不依赖后期补救;后期只做客观拦不住的事(配音/字幕/人工审)。**后期处理在 skill 流程内**(Step 7 · [C1-flow.md §13](C1-flow.md))——字幕烧录 + TTS 混入由 `post.cjs` 执行,本篇只管"后期 vs 直出"决策。

## §0 七类非量化质量因素(总表)

| # | 因素 | 阶段 | 源头写对(落点) | 验证(质检门) |
| --- | --- | --- | --- | --- |
| **Q1** | 前后一致性(主体/场景/风格/跨段锁) | 规划 | M1 角色锁 · M2 场景复制 · M3 风格锚 | 跨段首尾帧对比 |
| **Q2** | 常理与物理正确(解剖/重力/遮挡/时空) | 规划 | C1 §7 四维度 · M1 §4 · M2 §7 | 播放审解剖/重力/遮挡 |
| **Q3** | 风格与情绪一致(美学母体/情绪弧) | 规划 | M2 §6 风格锚 · README 美学母体 | 播放审色温/光比 |
| **Q4** | 崩坏控制(变形/穿模/乱码/漂移) | prompt | 正向常理锁 + 反模式清单 | 播放审崩坏 |
| **Q5** | 负面约束规范(正向锁替代 no- 堆砌) | prompt | §3 约束写法 | 终审约束段 |
| **Q6** | 配音/字幕后期(烧录/TTS 混入为主·同源/音画同步) | 后期 | M4 §6 · M5 §7 | 音画同步/同源核对 |
| **Q7** | 主观质检协议(质检门升级，逐镜审) | 验证 | §7 流程 | 逐镜人工审 |

> **一句话**:Q1-Q3 规划期锁死，Q4-Q5 prompt 期写锁，Q6 字幕/配音后期为主决策，Q7 收尾验证。写作规则(§4)与质量锁推导(§5)在 prompt 期执行。

## §1 Q1-Q3 一致性锁

四把锁在规划期全部上锁，缺一把就漂移。

### 1.1 四把一致性锁

| 锁 | 写法 | 翻车点 |
| --- | --- | --- |
| **主体锁** | 全片同一套角色四层关键特征(M1)，改一个词=漂移 | 中段换服装/换发型 |
| **场景锁** | 场景三层原样复制到每个含该场景的镜头(M2)，只改机位/动作 | 相邻镜头场景细节突变 |
| **风格锁** | 整段 1 个风格锚 + 美学母体(配色/材质/光比)照抄 | 风格词混搭 |
| **跨段锁** | 后段以前段末帧作首帧；SRT 与 TTS 同源 | 多段之间主体/环境跳变 |
| **关键帧锁** | 首尾帧由跨段锁(i2v/末帧)保持不变;中间关键姿态帧用详细文字描述焊进对应镜头块 | 中间关键姿态/转折动作漂移 |

### 1.2 抖动的根因与对策

- **根因**：镜头结构未 1:1 对应、Action/Camera 时间锚点不同步(见 [C1-flow.md §5](C1-flow.md))。
- **对策**：`Final Prompt` 的 `Action` 与 `Camera` 段按分镜镜号 1:1 展开，同一套时间锚点。

## §2 Q2 常理与物理正确

> 违背常理的画面观众一眼识破，信任度归零。完整四维度检查见 [C1-flow.md §7](C1-flow.md)。

| 维度 | 必查 | 反例 |
| --- | --- | --- |
| 物理规则 | 物体不凭空出现/消失、状态不突变、不穿墙、空间有物理隔离 | 满杯→空杯→满杯 |
| 社会规则 | 行为匹配场景、人物关系合理、行为与身份一致 | 礼仪小姐推机床 |
| 时间连续性 | 光线/色温不跳变、天气/季节一致、道具/人物状态随时间合理变化 | 雪夜 + 短袖 |
| 空间连续性 | 人物/道具相对位置一致、场景切换有过渡、空间布局稳定、多点光源统一 | 车间后方直接出办公室工位 |

## §3 Q4-Q5 防崩坏与负面约束规范(核心)

> **y-media 用"正向常理锁"替代传统 negative prompt**——堆 20 个 `no-` 反而污染 prompt；只把最易崩的 3-4 项用正向短语焊进 prompt。

### 3.1 正向常理锁(写进 prompt，不是 no-)

| 锁 | 写法(中文,焊进 prompt 前置锁) | 防什么 |
| --- | --- | --- |
| 解剖锁 | 主体解剖正确 | 多指/五官错位/肢体畸形 |
| 重力锁 | 物理正确 | 漂浮/反物理运动 |
| 材质锁 | 自然材质纹理 | 塑料感/穿模 |
| 稳定锁 | 画面稳定不闪烁 | 抖动/漂移 |
| 身份锁 | 与 `<图片1>` 保持主体一致 | 主体变形/换脸(i2v 必用) |

### 3.2 末尾负面约束段(最小集，焊死在 prompt)

```text
负面约束: 画面稳定不闪烁,无变形,无错字,无水印
```

- 只锁最易崩的 4 项，不堆砌
- 屏幕文字/字幕乱码 → 加 `无错字`；数字/品牌名用引号包裹并声明"按引号内文字原样渲染"
- **内容创作负面提示词**(§3 产出,题材/画面层 3-5 项)与本最小集**合并去重**后一并写入本段([C1-flow.md §11](C1-flow.md))

### 3.3 反模式清单

- **每 recipe 专属反模式表**(穿模/塑料感/乱码/漂移/颜色过艳)是防崩坏的"场景化清单"，见各 recipe §反模式。
- 通用反模式：主体变量在 prompt 中被反复改写、一段多个光源、风格锚 2-3 个。

## §4 写作规则(Step 5 写脚本时对照)

### 4.1 动作写法的关键约束

完整动作规则见 [C1-flow.md §6](C1-flow.md)(分镜表·主体动作列) + [M1-character.md §3](M1-character.md)。本段只列 **prompt 层的执行摘要**:

1. **每镜单动作 + 至少 1 个 micro-action**(头发/呼吸/眼睛/衣角/尾巴)
2. **写慢写连续**: "轻抬手腕" 优于 "挥手"；"缓步转身" 优于 "走动"
3. **不与光影/风格矛盾**: "微距" 不写 "大远景"；"治愈" 不写 "手持抖动"

### 4.2 镜头语言(引用 M3)

景别 / 机位 / 运镜 / 焦段景深 / 构图，以及镜头选择决策表，全部在 **[M3-cinematography.md](M3-cinematography.md)** 一处维护(职责收敛，本段不重复)。

**prompt 层执行摘要**(完整取词见 M3):
- 景别 5 级:远景 / 全景 / 中景 / 近景 / 特写
- 运镜 8 种:推 / 拉 / 横移 / 环绕 / 升降 / 手持 / POV / 推拉结合
- 三条铁律(L1-L3):单段 ≤2 个组合运镜；治愈/广告禁手持；数字分级写 prompt(技术参数不写，剧情爆点数字必须写)

## §5 质量锁推导(按决策链自动焊入)

> 质量锁不是"记得就加，忘了就没了"——它是**决策链的必然结果**。这一步在模板填写后、提交自检(§7.6)前执行。本段把 §0 的质量因素(Q1-Q7)按本次建模的决策链逐个推导，**自动决定**最终 prompt 必须焊入哪些锁。

### 5.1 推导表(按流程中已确定的决策)

| 决策链(已定) | 质量锁(中文直书) | 焊入位置 | 源自 §0 |
| --- | --- | --- | --- |
| 路径 = i2v 锚定 | 与 `<图片1>` 保持主体一致 | **前置锁** + `★ 镜头组` 每镜块内 | Q1 主体锁 |
| 多镜 / 分段 | 主体四层原样复制(镜镜一致) + 后段前置"以上段末帧为首帧"(首尾帧保持不变);中间关键姿态帧用详细文字描述焊进对应镜头块 | **前置锁** + `★ 镜头组` 段首 | Q1 跨段锁 + 关键帧锁 |
| 有字幕(后期烧录) | 文案零错字逐字核对(R5);屏幕无文字 → 无文字 | `负面约束` 段 | Q5 |
| 治愈/慢节奏/固定风格锚 | 画面稳定不闪烁 + 整段只写 1 个风格标签 | **前置锁** + `★ 风格锚` | Q4 稳定锁, Q3 风格锁 |
| 剧情/情绪弧(C 骨架) | 情绪色温对撞(冷→暖) + 静音法则 | 对应镜头的镜头块描述 | Q3 情绪一致 |
| 有产品展示/道具 | 常理锁: 主体解剖正确 + 自然材质纹理 | **前置锁** + `负面约束` 段 | Q2 物理规则 |
| 仅氛围/空镜 | 重力锁: 物理正确 + 画面稳定不闪烁 | **前置锁** + `负面约束` 段 | Q2+Q4 |

> **推导规则**:取表中所有命中项,去重后合并到 **前置锁**(开头 1-2 行)与 `负面约束` 段,主体锁写在 `★ 镜头组` 每镜块内,场景锁确保 `★ 场景` 全段原样复制。**至少命中 3 项**——如果少于 3 项,说明决策链有遗漏。

### 5.2 运行时推导(自检清单)

用以下 3 问确认锁已焊入:

1. **决策链全了?** 路径/镜数/字幕/风格/骨架走向 5 项是否都已确定？
2. **锁已推导?** 按上表取所有命中项，合并去重到对应位置。
3. **锁已完整?** 主体锁是否在**前置锁**与每镜块内？约束锁是否在 `负面约束` 段？场景锁是否整段复制？

### 5.3 与质量因素的关系

- §0 管"质量有哪些维度、怎么验证"——**是什么**
- 本段管"当前这次该带哪几把锁"——**怎么做**
- 两段协作: §0 提供弹药库，本段根据决策链装填

> 质量锁推导是本文件的职责，因为只有拼 prompt 时掌握了所有建模决策。质检门不负责推导——质检说"要锁"，本篇说"锁哪把"。

## §6 Q6 字幕/音频后期:后期为主(烧录 + TTS 混入)

> **后期是默认，且处理在 skill 流程内**(Step 7 · [C1-flow.md §13](C1-flow.md)):字幕文案进 SRT 源成片后烧录、口播文案进 TTS 源合成混入——确定性、零错字可控。判定入口见 [M4-audio.md §6](M4-audio.md) 与 [M5-subtitle.md §7](M5-subtitle.md)。

### 6.1 后期决策模型

| 态 | 含义 | 何时用 | 字幕例 | 配音例 |
| --- | --- | --- | --- | --- |
| **后期(默认)** | 成片后处理,确定性可控 | 字幕/配音的默认路径 | 文案→SRT源→`post.cjs burn` 烧录 | 口播→TTS源→`post.cjs tts+mux` 混入 |
| **直出(特殊)** | 模型直接渲染,零后期 | 需求显式要求"AI 直接渲染文字/音画直出",或本机缺 ffmpeg/edge-tts | 写进 prompt `★ 文字叠加`(见 [M5-subtitle.md §7.2](M5-subtitle.md)) | 需求显式要求 AI 音画直出 |

**决策原则**:字幕/配音默认走后期,为确定性(零错字、音画同步)而后期;直出仅用于显式特殊需求或工具缺失的降级。

### 6.2 字幕:后期烧录(核心)

字幕文案进 SRT 源,成片后 `post.cjs burn` 后期烧录——确定性、零错字可控。**不写进 prompt 让模型渲染**(模型渲染文字易错字/水印)。

**字幕后期(SRT 源)写法** — 文案 + 时机 + 位置 + 样式写进 brief 的 SRT 源(M5 §4),成片后烧录:

```bash
# 文案 → SRT → 烧录(样式在 M5 §4.2 锁定)
node core/post.cjs burn <v>.mp4 --srt <name>.srt --out <name>.sub.mp4
```

```
1
00:00:00,500 --> 00:00:02,300
三块九,包邮到家

2
00:00:02,400 --> 00:00:04,000
这个材质,是纯棉的
```

**字幕要求**:
- 文案**零错字**(R5)，品牌名/型号/成分名逐字核对，官方拼写原样使用
- 单句 ≤12 字，超了拆两屏
- 位置/样式全片锁一套(见 [M5-subtitle.md](M5-subtitle.md))
- 出现时机比口播提前半拍，让静音用户先看到

**字幕直出(特殊需求/能力缺口)** — 仅当需求**显式要求"AI 直接渲染文字"**(不烧录)或本机缺 ffmpeg 时,才把字幕写进 prompt 让模型直出(见 [M5-subtitle.md](M5-subtitle.md) §7)。**后期烧录是默认,直出是特殊需求**。

**字幕+配音同源(时间轴一致)** — 字幕/配音都走后期,同一份文案 → 同时产出 SRT + TTS,时间轴以 storyboard 为基准(字幕比口播提前半拍)。爆点镜的字幕入场与 BGM 鼓点同帧(±0.1s);口播文案(换气/尾音/避免播音腔)与字幕文案逐字一致。

```
storyboard 镜号/时长 → SRT 时间轴(M5) + TTS 时间轴(M4) 同源对齐
爆点镜: 字幕入场 与 BGM 鼓点同帧(±0.1s), 价格/数据"先断后响"
```

### 6.3 音频进 prompt(核心)

> **R3**:环境音/BGM 用**中文描述**写进 `★ 音频` 段让模型直出;**人声口播只作 TTS 源**,成片后 edge-tts 合成 + 混入(post.cjs tts+mux)。

```
★ 音频:
- Ambient: 撕包装"嘶啦" + 冰块碰撞"咔啦" + 厨房背景环境音
- BGM: 清新民谣(木吉他+钟琴)，轻快治愈，开头淡入，末镜淡出只留环境音
- Voice(TTS 源,后期): 女声旁白 "这虾仁也太鲜了" (自然口条，关键词前微停) → edge-tts + mux
```

- 环境音/BGM 每镜都设计，不写 BPM/dB 数字(展示层才写)
- 环境音换场景就换；无对白时写生理音(呼吸/衣物摩擦)
- 关键音效点标镜次+时机
- 人声口播作 TTS 源,**不写进 prompt 让模型渲染人声/口型**

### 6.4 后期硬约束

- **配音默认中文**(强约束)：非方言/外语/特定音色显式要求时，不推断其他语言。
- **SRT 与 TTS 同源**：同一份口播文案 → 同时产字幕 + 配音，时间轴一致。
- **音画同步**：字幕比口播提前半拍；BGM 鼓点与数据字幕同帧(±0.1s)。
- **字幕不遮产品**：数据/CTA 放画面下 1/3。

## §7 Q7 主观质检协议 + 提交前自检

> 客观校验(post.cjs probe)管参数，本篇管"看起来真"。下载后直接播放成片人工审，决定接受/重生成；**禁止抽帧**——质检只播放成片人工审，不用 `post.cjs frames` 抽帧作审查替代。完整质检门见 [C1-flow.md §14](C1-flow.md)。

### 7.1 流程

```
下载 → 客观校验(probe) → 直接播放成片 → 逐镜审 4 项 → 跨段首尾核对 → 判定
```

### 7.2 逐镜审 4 项(Q1/Q2/Q3/Q4)

| # | 审什么 | 对应因素 |
| --- | --- | --- |
| 1 | 常理：解剖/重力/遮挡/时空匹配 | Q2 |
| 2 | 一致性：主体/场景/风格不漂移 | Q1 |
| 3 | 崩坏：变形/穿模/乱码/抖动 | Q4 |
| 4 | 风格：色温/光比/美学母体统一 | Q3 |

### 7.3 跨段首尾核对(Q1)

多段成片，逐段核对"上段末帧 vs 下段首帧"主体/环境/光影是否连续。

### 7.4 判定

| 结果 | 动作 |
| --- | --- |
| 全过 | 接受 |
| 单段字幕/配音错 | 局部重生成该段(只重烧错段) |
| 主体漂移/常理崩坏 | 修 prompt 后整体重生成 |

### 7.5 闭环定位(质检结果回写决策链)

质检门不是终点，是下一轮的输入。被打回的镜，按原因回写对应层修锁，形成 **"建 → 拼 → 验 → 修"** 闭环:

| 打回原因 | 回写层 | 修复动作 |
| --- | --- | --- |
| 锁没焊上(主体漂移/崩坏) | §5 质量锁推导 | 按推导表补锁/补强到对应位置 |
| 字幕/配音后期翻车或工具缺失 | §6 后期为主决策 | 按缺口降级:显式直出需求或换工具(剪映) |
| 建模缺项(常理/情绪违和) | M1-M5 建模文件 | 补 schema 必填项后重拼 |
| 客观参数错(时长/帧率) | post.cjs 校验 | 修参数重生成 |

> 同类原因第二次出现，说明该锁还没焊进决策链——是规则缺口，不是运气问题。轮次收敛是质量稳定的信号。

> 能力缺口不伪造：本机缺 ffmpeg/ffprobe 时如实报告并给降级路径，不从文件名/默认值推断。

### 7.6 提交前自检(写脚本后、提交生成前)

- [ ] 八要素齐全
