## §1 路径判定(决策一次,后续不切换)

**铁律 R1(见上表)**:剪辑 vs 生成、i2v 锚定 vs 纯 t2v,决策一次,后续不切换——生→剪→生 = 主体漂移 + 成本翻倍。决策后整条视频全程不混用,禁止同一段前后混用不同路径。

| 情况 | 路径 | 保真度 | 动作 |
| --- | --- | --- | --- |
| 已有任务(带 Provider + task.id) | 查询/下载 | — | 直接恢复 |
| 已有素材,重排+字幕+BGM | **E 纯剪辑** | 与素材完全一致(无漂移) | ffmpeg/剪映一次剪完;storyboard 只含分镜表 + 接续菜谱 |
| AI 新画面 · 人像/产品/多人/品牌(需外观保真) | **G-i2v 锚定(默认)** | 参考图锁定外观+环境,一致性最高 | 先出/指定参考图 → image-to-video → Provider |

## §3 内容创作 · 写故事(需求 → 故事文本)

### 3.1 Brief 解构(先解析为三槽位)

把 brief 解析为三个槽位,并用明确的默认值补缺(在文档表头 `默认假设` 行记录):

| 槽位 | 需要确定什么 | 未知时的默认值 |
| --- | --- | --- |
| 主题/产品 | 主体,1-3 个关键点或卖点,可用的素材 | 取自请求;确实缺失时问一次 |
| 人群/受众 | 受众,他们的痛点或兴趣 | 该主体类型的常见受众 |
| 目标 | 认知(brand) / 兴趣(seeding) / 转化(conversion) | 根据请求决定,无固定默认值 |

目标决定基调、节奏和字幕路线。三种目标地位平等。

### 3.2 故事四要素

> **位置**:套骨架之前。先把用户需求(brief)写成**自由文本故事**,作为分镜/字幕/配音的唯一源头;骨架只定"怎么切/多快",**不重写"讲什么"**。需求是片段的(只有一个卖点/一个画面),补成完整故事;需求自带情节(情感/溯源/品牌),提炼主线,不重写。

| 要素 | 定义 | 示例(骨架B 溯源) |
| --- | --- | --- |
| 人物画像 | 主角是谁、动机是什么 | 卖山货的返乡姑娘,想让老手艺被看见 |
| 主线 | 一条清晰因果链(起→承→转→合) | 清晨收山货 → 山路难走 → 遇到返乡人 → 手艺被认可 |
| 情节 | 2-4 个具体事件/冲突,与 7s 钩子对齐 | 钩子"刚下火车来看娃";冲突:山路塌方 |
| 情绪弧 | 情绪走向(冷→暖/压抑→治愈),与骨架匹配 | 疲惫 → 温情 → 治愈 |

**产出**:`<name>.video-brief.md` 的 `故事` 区块(放在分镜表格之前),一段 3-5 句自由文本 + `负面提示词` 区块(3-5 项"不要什么",题材/画面层,写脚本时并入 Final Prompt 的 `负面约束` 段,§11)。

**自检**:
1. 故事自洽吗?人物动机一致、情节因果完整、情绪弧完整
2. 骨架没重写故事吗?骨架只负责镜头数/节奏/字幕路线(§4)
3. 故事能驱动分镜吗?每个情节点都能映射到分镜镜号
4. 负面提示词列了吗?题材/画面层 3-5 项"不要什么"(如无对白/无字幕乱码/无棚拍感)已写入 brief

## §4 叙事骨架(A/B/C 三选一)

先按 §3 写好故事,再选骨架;骨架决定镜头数、节奏和字幕路线——**套在故事上,不重写故事**。

| 骨架 | 用途 | 镜头数 | 单镜时长 | ★ 密度 | 7s 钩子 | 段均字幕 | 音频节点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **A: showcase** (测评/利益/ASMR/变装/演示) | 信息密集、节奏快 | 9-12 | 1.0-2.5s | ≥5 ★,每 3s 一颗 | 0-2s,视觉/字幕钩 | 4-6 条(钩/卖点/数据/CTA) | 3-5 个(钩子音效+卡点+CTA) |
| **B: narrative** (情感/故事/溯源/品牌) | 情绪弧线、节奏较慢 | 5-8 | 2.0-5.0s | ≥4 ★,首镜/中点/末镜必 ★ | 0-3s,视觉/情绪钩 | 0-2 条(无字幕或极简) | 1-2 个(起/收) |
| **C: 共情子型** (共情/自嘲/治愈/打工人) — B 的情绪强子型 | 情绪共鸣;共情→自嘲→转折→金句 | 6-10 | 2.0-4.0s | ≥5 ★,四拍各 1 ★ | 起拍 0-2s,视觉/OS心声 | 3-5 条(钩/转/合拍金句) | 4 个(每拍 1 个情绪节点) |

适用于所有骨架的规则:
- 每 15s 保持 **1-3 个关键点**;再多就需要拆段(§8)。
- **前 7 秒内回收钩子**(视觉爆发或情绪爆发),否则完播率下降。
- 在封面级镜头上标 `★`;一个 15s 段至少 5 颗,最少每 3s 一颗。
- 镜头数是**规划层**上限;提交层(prompt)按 §5 规则 1:1 对应,默认不合并相邻镜头。

### 4.1 骨架 A · showcase(测评/利益/ASMR/变装/演示)

**核心**:快切、平行、卖点罗列。9-12 镜,单镜 1.0-2.5s,配含字幕(后期烧录)路线。

**典型 15s 结构**:
```
镜1 1.5s 钩子   极近景/低角度仰拍   ★  字幕①钩子(痛点/悬念/反常识)
镜3 1.8s 卖点1  微距特写            ★  字幕②数据卖点1
镜5 2.5s 卖点3  低角度侧逆光/缓抬   ★  字幕②卖点3 或 ③背书
镜7 2.0s 高潮   内部微距/捕捉快动作 ★  字幕②核心数据爆点(7 秒高潮镜)
镜8 1.0s 收尾   全景顶部            ★  字幕④CTA(点+利益+紧迫)
—— 15s / 8-12 镜 / ★≥5 / 字幕覆盖①②④
```

### 4.2 骨架 B · narrative(情感/故事/溯源/品牌)

**核心**:线性、起承转合、情绪弧。5-8 镜,单镜 2.0-5.0s。产品作"情绪触发器",不罗列参数。

**典型 15s 结构**:
```
镜1 2.5s 起·铺垫  特写/推镜       ★  字幕①悬念(时间/地点/心声)
镜3 3.0s 承·揭示  特写/平摇       ★  字幕③背书(品牌/情感tag)
镜4 3.0s 承·冲击  特写/手持微晃   ★  字幕⑤情绪tag(泪目/颤抖,面部特写非产品)
镜5 2.5s 转·推进  过肩/慢推       ★  两主体互动(戴戒/递物/拥抱)
镜6 1.5s 合·定格  中景/缓拉焦外   ★  字幕④品牌slogan(替代硬CTA)
—— 15s / 5-8 镜 / ★≥5 / 字幕覆盖①③④
```

**B 的取向**:情绪爆点镜给面部特写而非产品;7 秒高潮是情绪反转不是视觉爆点;对白+环境音+BGM 情绪节点成对出现;结尾用品牌 slogan/情感 tag 而非硬CTA。

### 4.3 骨架 C · 共情子型(B 的强情绪变体)

> **C 是 B 的子型,不是独立骨架**。当 B 的情绪重点是"共情/自嘲/打工人式"时使用 C。三条 C 独有的节奏规则:
> 1. **情绪色温对撞**:压抑段(起/承)用冷灰蓝+荧光白(现实感),治愈段(转/合)用暖黄橙(反差治愈);换色点正好落在转折拍,光影同步从硬冷光过渡到柔暖光
> 2. **7s 数字/反差爆点**:不要视觉爆点,要"数字/反差"作为情绪爆点;数字爆点前 0.5-1s 全断(静音法则)
> 3. **末镜金句/反问留白**:不写硬 CTA,改用黑底金句(末镜或黑屏)+ 关键词黄底高亮;设问引导互动

**四拍节奏表**:

| 拍 | 情绪 | 时长占比 | 职责 | 音频 |
| --- | --- | --- | --- | --- |
| 起 | 共情/痛点 | ~25% | 真实疲惫细节直入, 7s 内出钩子 | 环境音 + 纯OS心声 |
| 承 | 自嘲/吐槽 | ~35% | 荒诞细节堆叠, 节奏渐快 | BGM 鼓点渐重,音画卡点 |
| 转 | 治愈/温柔 | ~25% | 情绪软着陆, 画面转亮 | BGM 切换,前 0.5-1s 静音留白 |
| 合 | 金句/收尾 | ~15% | 黑底金句字幕收束 + 互动设问 CTA | BGM 淡出只留环境音 |

### 4.4 骨架速选(决策树,2 步定位)

```
Step 1: 目标是否是"转化/带货/强信息"?
   是 → 骨架A (showcase · 密信息快节奏)
   否 → 进入 Step 2

Step 2: 主体是否有"人物/故事/情绪弧"?
   是 → 骨架B (narrative · 慢切) 或 骨架C (B 的共情子型)
        —— 情绪以"克制/美感"为主 → 骨架B
        —— 情绪以"共情/自嘲/金句"为主 → 骨架C
   否 → 骨架A (美学导向的 showcase 同样适用)
```

> **判断口诀**:看文案里的情绪词。"高性价比/爆款/必入"是 A;"治愈/静谧/品牌感"是 B;"上辈子/破防/家人们"是 C。**先定骨架,再填表**。

### 4.5 钩子模板(置于镜头表顶部作对照)

| 场景 | 开场视觉 | 文字/音效 |
| --- | --- | --- |
| 测评/演示 | 疑问前置字幕 + 产品全景 | "这个很火的到底好不好用?" |
| 利益/转化 | 价格锚点 + 产品硬切 | 大字幕 "3.9元包邮" |
| ASMR/感官 | 感官特写 + 撕包装/切开音效 | 无口播,全声音 |
| 溯源/故事 | 场景直入 + 人物出镜 | "刚下火车来看娃" |
| 品牌/形象 | 氛围场景 + 品牌元素 | slogan 前置 |
| 共情/自嘲(C) | 疲惫日常直入 + 内心 OS 字幕 | "上辈子到底造了什么孽" |

## §5 镜头结构(规划层 vs 提交层)

### 5.1 默认规则(1:1 镜号对应)

上面的镜头数(5-12)是**规划层**数字,用于分镜表和人工评审。**提交层**(写到 `Final Prompt` 里的内容)默认 1:1 对应:**每个分镜一行,每个镜号一个时间段,动作与镜头语言两段都用同一组时间锚点**。

| 生成模式 | 镜头结构写法 | 时间表达 | 说明 |
| --- | --- | --- | --- |
| **单段直出 i2v 锚定**(y-media 默认) | 按分镜表 1:1 对应;禁止主动合并;外观由参考图锁定,Action 只写"怎么动" | 时间锚点(每个镜号一段) | 镜号与时间段一一对应,镜头边界、主体动作、转场最清楚 |
| **多段生成 + 剪辑**(拆段 + 拼接) | 每段独立表达自己的镜头结构 | 每段独立 | 超过 Provider 单段硬上限时使用 |

**规则**: `Final Prompt` 的 `★ 镜头组` 每镜一块,镜号与时间锚点 1:1 对应;动作与机位运镜锁在同一个时间块内。

### 5.2 时间表达方式(3 种,按需选)

| 方式 | 强度 | 写法 | 适用 |
| --- | --- | --- | --- |
| 精确时间锚点 | 最强 | `0.0-5.0s: ...` | 镜头边界、动作阶段或转场需要明确时 |
| 画面编号 | 中等 | `Shot 1: ...` | 多个画面单元需要分层描述时 |
| 动作流连接词 | 弱/自然 | `then` / `suddenly` / `as` | 单一连续动作或短段落 |

## §6 分镜表列(Shot Table Columns)

每一镜都要填满每一列。精确胜过散文;每列回答一个问题。

| 列 | 规则 | 示例 |
| --- | --- | --- |
| 镜号 | 从 `S01-01` 起 | S01-03 |
| 时长 | 精确到 0.1s;段总和与目标时长一致 | 1.8s |
| 景别与视角 | 景别 + 机位角度 | 微距特写,低角度仰拍 |
| 运镜 | 运镜 + 速度 + 方向;一镜至多 2 个动作 | 缓推,跟随虾仁滑落 |
| 光影 | 方向 + 色温 + 光质 | 45°侧光,柔光 |
| 主体动作 | 具体、单一的动作 + 至少一个 micro-action | 手撕开包装袋,冰块碎粒滑落 |
| 场景/道具 | ≥3 可辨识元素 + 1 个光源;背景加 1-2 个低速动态元素 | 前景冰块碎粒/中景包装袋/背景厨房台面,晨光侧光+水珠缓慢蒸发 |
| 音频三层 | ① 人声 ② 环境音+关键音效 ③ BGM 节点 | (环境)撕包装"嘶啦"+冰块碰撞"咔啦"/(BGM)木吉他扫弦淡入 |
| 字幕(SRT 源,后期烧录) | [M5-subtitle.md](M5-subtitle.md);文案+时机+位置+样式作 SRT 源,成片后 post.cjs burn 烧录,**不写进 prompt 让模型渲染** | ①"这虾仁,也太鲜了!"·上1/3·白字黑边 |
| 视觉重点 | `★` = 封面级 | ★ |

**背景真实感 3+1 规则**(任何场景都适用):`[具体场所] + [3 个可命名道具/纹理] + [1 个光源]`。避免纯渐变或空棚背景;加入动态元素,画面才不会冻住。每个场景从四种动态中选 **1-2 个缓慢的局部动态元素**:

| 动态类型 | 示例 |
| --- | --- |
| 人物动态 | 背景虚化人流走动 / 邻桌客人交谈 |
| 自然动态 | 纱帘轻飘 · 树影摇曳 · 水面波光 |
| 光影动态 | 光斑缓移 · 明暗呼吸 |
| 粒子动态 | 蒸汽升腾 · 尘埃浮动 |

### 6.1 展示层 vs final prompt(分镜表 vs 中文直书)

**final prompt 直接中文,不翻译、不换算**:分镜表(展示层)用具体数字记录便于归档;**final prompt(中文直书)用自然中文重述"画面长什么样"**,不把技术参数(K/dB/BPM/焦段)塞进去,也不做英文语义换算——直接写人话(如 `暖金色晨光` `柔光侧光`)。两层的差异只在"记录精度",不是"语言":

| 字段 | 展示层(分镜表,人读·归档) | final prompt(模型读·直接中文) |
| --- | --- | --- |
| 色温 | 4500K | 暖金色晨光 |
| 光质 | 柔光 / 硬光 | 柔光 / 硬直射光 |
| 光位 | 45°侧光 | 从左侧打来的侧光 |
| 焦段 | 16mm | 广角,浅景深,电影镜头感 |

**铁律**: 技术参数(色温K/焦段/角度)只在展示层记录,final prompt 用自然中文描述;**剧情爆点数字(金额/名称/年龄/成分/型号)例外——必须原样写进 prompt**(见 [M3-cinematography.md](M3-cinematography.md)),因为模型要直出这些数字。

## §7 事件逻辑自洽(R6 通用四维度检查清单)

**核心原则**:场景 / 动作 / 时间 / 天气 / 服装 / 道具必须**相互一致**,违反常识的组合一旦出现,短视频观众一眼识破,信任度归零。**必须在分镜表规划阶段就把好关**。

**维度 1: 物理规则(Physical Laws)**

| 检查项 | 解释 |
|--------|------|
| 物体不能凭空出现/消失 | 道具/人物入场退场必须有动作依据 |
| 物体状态不能突变 | 状态变化必须合理:满→半满→空,不能满→空→满 |
| 人物不能穿墙/穿物 | 人物的移动路径必须经过合理的空间过渡 |
| 空间关系一致性 | 相邻空间之间必须有物理隔离描述 |

**维度 2: 社会规则(Social Norms)**

| 检查项 | 解释 |
|--------|------|
| 行为匹配场景 | 场景的社会规范限制可执行的动作 |
| 人物关系合理 | 角色间的互动方式符合其关系(师徒/上下级/情侣) |
| 行为与身份匹配 | 角色的职业/身份与行为一致 |

**维度 3: 时间连续性(Temporal Continuity)**

| 检查项 | 解释 |
|--------|------|
| 光线/色温不跳变 | 同一场景内光线色温不能突变 |
| 天气/季节一致 | 相邻场景的天气和季节不能矛盾 |
| 道具状态随时间合理变化 | 道具的消耗/磨损随时间推进 |
| 人物状态合理变化 | 妆容/发型/疲劳度随时间推进 |

**维度 4: 空间连续性(Spatial Continuity)**

| 检查项 | 解释 |
|--------|------|
| 人物/道具相对位置一致 | 不同机位下,人物与道具的相对位置不变 |
| 场景切换有过渡 | 空间转换必须有动作或运镜过渡 |
| 空间布局稳定 | 同一场景的家具/装饰/布局不突变 |
| 多点光源统一 | 多光源场景中,各光源的色温/方向一致 |

### 7.1 自检四问(填完分镜表骨架后)

逐项回答,任一为否就回头改:
1. **物理规则维度**: 道具/人物的入场退场有动作依据吗?状态变化合理吗?空间关系有物理隔离吗?
2. **社会规则维度**: 行为匹配场景吗?人物关系合理吗?行为与身份一致吗?
3. **时间连续性维度**: 光线/色温不跳变?天气/季节一致?道具状态随时间合理变化?
4. **空间连续性维度**: 人物/道具相对位置一致?场景切换有过渡?空间布局稳定?

> 服装-场景细表见 [M1-character.md §4](M1-character.md);时间-天气-光线细表见 [M2-scene.md §7.1](M2-scene.md)。

## §8 时长与分段策略 + 制片决策

### 8.1 时长与分段

- **单段默认**:优先一段。硬上限是**动态的**,取自 Provider `capability_limits`。
- **剧情类(骨架 B/C)允许分段**:铺垫/反转/收尾信息量大时,拆成每段顶格到上限的 N 段(如 30s = 2×15s)。分段后每段一个独立 prompt、段内镜序自洽、段与段之间角色/环境/光影保持一致。
- 超过单段上限时,生成前必须问用户选择:① 分开(默认推荐)N 段独立交付;② 合并N段 + 附拼接菜谱。

> **Provider 上限(单段时长/帧数/画幅/帧率)不在此硬编码**:以 [providers/manifest.cjs](../../providers/manifest.cjs) 的 `capability_limits` 为唯一来源(契约见 [core/provider-contract.md](../../core/provider-contract.md)),运行时可经编排引擎 `listCapabilities` 读取。

### 8.2 多段一致性(N 段规划阶段必做)

- 每段独立满足完整叙事(独立 brief、独立钩子、独立音频节点)。
- 段间一致性: 美学母体照抄,后段以前段末帧作首帧(首尾帧保持不变),一套锁定的字幕/音频风格;中间关键姿态帧用详细文字描述(关键帧锁)焊进对应镜头块。
- 默认**竖屏 9:16**,除非用户另有要求。

### 8.3 制片决策(Producer Check)· 写分镜前先过一遍

制片管"范围/可行性/降级",把散落在各处的决策点收拢成一张自检表。**在填分镜表前过一遍**,避免中途返工。

| # | 决策点 | 依据 | 结果写进 |
| --- | --- | --- | --- |
| P1 | 路径判定(剪辑/生成) | §1 路径判定 | brief 表头 `生成路径` |
| P2 | 单段 vs 分段 | R2 单段顶格;剧情类(骨架 B/C)信息量大允许分段;超 Provider 单段上限才拆(§8) | §8 分段决策 |
| P3 | 主体保真路径(i2v/t2v) | §1 | brief 表头 `默认假设` |
| P4 | **降级预案**(后期能力缺口时) | 缺 ffmpeg/edge-tts→字幕/配音降级为 prompt 直出或剪映([M5-subtitle.md §7](M5-subtitle.md)·[M4-audio.md §6](M4-audio.md)) | 伴生文档 Notes |
| P5 | **素材复用 vs 全生成** | 有可用实拍→剪辑路径;无→生成。素材复用更省,但保真度低于 i2v 参考图 | 路径判定结果 |

> **制片视角一句话**:这一条视频是"一段顶格生成"还是"拆 N 段",字幕/配音走后期还是直出,降级走哪条路,动笔前定死,别做一半再改。

## §9 规划自检(提交生成前)

> 规划层自检;prompt 层自检(八要素/质量锁/字幕零错字/SRT·TTS 源/no text/单段顶格)见 [C2-quality.md §7.6](C2-quality.md)。本篇管"规划对不对",C2 §7.6 管"prompt 写对没"。

```
1. 制片决策:路径/分段/保真/降级/素材(P1-P5)已定死(§8)
2. 路径决策:剪辑/生成,表头锁定(§1)
3. 故事已产出且自洽(§3),骨架套用但不重写故事:A/B/C(C 是 B 的共情子型)(§4)
4. 镜头结构:1:1 镜号对应,Action/Camera 同步时间锚点(§5)
5. 镜头语言:景别/机位/运镜取词自 [M3](M3-cinematography.md),≤2 运镜
6. ★ 密度:15s 段 ≥4 颗;每颗 ★ 含 ① 主体清晰 ② 视觉重点 ③ 美学母体 ④ 可裁切竖版封面(§4)
7. 7s 钩子:钩子镜的视觉/字幕能在 0.5s 内抓住注意力,不是"产品缓缓入画";不达标重写钩子镜(§4)
8. 时长加和:每镜 0.1s 精度,段总和 = 目标时长;不匹配调最短/最长镜,不动骨架(§4)
9. 分镜表列:填满,3+1 场景元素+动态满足(§6)
10. 事件逻辑:R6 四维度检查通过(§7)
11. 超上限时:生成前走 split-or-merge 用户确认(§8)
```

## §10 伴生文档结构(4 段)

每段视频产出一个 Markdown 文件,保存在预期输出旁边:`<name>.video-brief.md`,其中 `<name>` 与视频的 `output.filename` 主干一致。

**伴生文档顺序固定**(4 段;`Final Prompt` 一定在最后):

| # | 区块 | 必填 | 说明 |
| --- | --- | --- | --- |
| 1 | **视频主要目标** | 必填 | 一行:`产品/主题 × 人群 × 目标(认知/兴趣/转化) × 骨架(A/B/C) × 时长 × 画幅(默认9:16竖屏)` |
| 2 | **故事(创作内容)** | 必填 | 独立区块:人物画像/主线/情节/情绪弧 + `负面提示词`(3-5 项,见 §3);负面提示词并入 Final Prompt 的 `负面约束` 段(§11) |
| 3 | **分镜表格** | 必填 | 每镜一行,表头锁定 `默认假设` / `音频策略` / `美学母体` / `视听路线`;字幕/配音文案进 SRT/TTS 源(后期烧录) |
| 4 | **Final Prompt(中文直书)** | 必填,**始终放最后** | 完整多镜 prompt,`★ 镜头组` 每镜一块,外加环境音/BGM 设计(§11) |

> **可选扩展项**(不破坏 4 段结构):
> - **Inputs**(i2v 参考图/起止帧):进伴生文档表头的 `默认假设` 行
> - **Generation** 元数据(Provider/model/task.id/参数):由编排引擎追加到伴生文档之后

完整可工作的实例见 [C4-example.md](C4-example.md)。

## §11 写脚本:Final Prompt + SRT/TTS 源(Step 5)

把分镜表(§6)落成可直接提交的 `Final Prompt` 与字幕/配音源:

- **模板 + 规则**:拼 prompt 用 [C3-prompt-craft.md](C3-prompt-craft.md)(八要素模板+拼接顺序) + [C2-quality.md](C2-quality.md)(质量+写作规则:动作/镜头/字幕/音频/质量锁/自检)。
- **直接中文**:分镜表展示层的技术参数(色温 K/焦段/角度)在 final prompt 用自然中文重述,不堆数字、不英文换算(§6.1);**剧情爆点数字(金额/名称/年龄/成分/型号)必须原样写进 prompt**。
- **字幕/配音源**:字幕文案进 SRT 源、口播文案进 TTS 源,均走后期(§13),不写进 prompt 让模型渲染;prompt `★ 音频` 段只承载环境音/BGM 直出。
- **质量锁**:按 [C2-quality.md §5](C2-quality.md) 推导表——路径/镜数/字幕/风格/骨架既定 → 自动决定焊哪些锁(主体锁/跨段锁/常理锁/稳定锁/负面约束)到 prompt 对应位置。
- **内容创作负面提示词合并**:brief `故事` 区块后的 `负面提示词`(§3) 与 C2 质量锁的 `负面约束` 段合并去重,作为最终 `负面约束` 输出。

## §13 输出与后期:字幕/配音(Step 7)

### 13.1 视频输出文件

文件结构同 §10:`<name>.video-brief.md`(4 段,`Final Prompt` 最后)含分镜表 / Final Prompt / SRT 源 / TTS 源;锚定参考图进 brief 表头 `默认假设`(references/image_paths)。字幕/配音走后期(§13.2),写法见 [M5-subtitle.md](M5-subtitle.md) / [M4-audio.md](M4-audio.md)。

### 13.2 后期处理(字幕/配音)

字幕与配音默认走后期,SRT 与 TTS **同源**(同一份 storyboard 文案),保证音画同步:

```bash
# 1) 字幕烧录(文案→SRT→烧录;样式在 M5 §4.2 锁定)
node core/post.cjs burn <out>.mp4 --srt <name>.srt --out <name>.sub.mp4
# 2) 配音 TTS(口播文案→音轨;中文默认 zh-CN-XiaoxiaoNeural)
node core/post.cjs tts --text "<口播文案>" --voice zh-CN-XiaoxiaoNeural --out <name>.voice.mp3
# 3) 配音混入(保留环境音/BGM,叠加人声)
node core/post.cjs mux <name>.sub.mp4 --audio <name>.voice.mp3 --out <name>.final.mp4
```

> 能力缺口不伪造:本机缺 ffmpeg 或 edge-tts 时,post.cjs 抛 `capability_gap` 并附可直接执行的菜谱;补齐工具后重跑该步。

## 阶段 D · 验证与交付(Step 8)

## §14 质检门(验证成片)

下载后跑一遍客观校验 + 直接播放成片人工审,决定接受/重生成。**禁止抽帧**——成片已可内联播放,直接播放完整视频人工审比抽帧样张更全面,不用 `post.cjs frames` 抽帧作审查替代。**非量化质量因素(一致性/常理/防崩坏/负面约束/后期)的完整清单与逐镜审协议见 [C2-quality.md](C2-quality.md)**:

| 检查 | 方法 | 不达标时 |
| --- | --- | --- |
| 时长/宽高/帧率 | ffprobe 客观校验 | 参数不符 → 重生成 |
| 文件完整性 | 存在 + 大小 > 0 + 是 mp4 | 异常 → 重提任务 |
| 违背常理(解剖/物理/连续性) | 播放成片人工审 | 漂移 → 修正后重生成 |
| 一致性/崩坏/风格(C3 Q1-Q4) | 播放成片逐镜审 + 跨段首尾核对 | 漂移/崩坏 → 修 prompt 重生成 |
| 字幕零错字 + 音画同步(C2 Q6) | 播放成片核对 + 配音对齐时间轴 | 错字/不同步 → 只重烧该段/重跑 TTS |

只有客观校验通过 + 人工审片无问题才接受(R6 兜底)。

> 能力缺口不伪造:本机缺 ffmpeg/ffprobe/edge-tts 时如实报告并给降级路径,不从文件名/默认值推断。

## §15 失败呈现与迭代引导

> 结果不达标时,**如实呈现失败原因 + 给一条可执行的修复路径**,不静默重试、不伪造成片。

| 失败/打回 | 呈现 | 引导 |
| --- | --- | --- |
| 生成任务失败(Provider/task 错误) | 报告 Provider 报错原文 + 任务 id | 重提任务,或切 Provider 重试 |
| 质检客观参数不符(时长/宽高/帧率) | 报实测值 vs 目标值 | 修参数重生成 |
| 主体漂移/崩坏/常理违和 | 报播放成片证据 + 命中的质量锁 | 回 [C2-quality.md §5](C2-quality.md) 补锁,重拼 prompt 后整体重生成 |
| 字幕/配音后期翻车 | 报错字/乱码/不同步/音色证据 | 只重烧该段 SRT 或重跑 TTS;能力缺口按 [C2-quality.md §6](C2-quality.md) 降级 |
| 能力缺口(缺 ffmpeg/edge-tts 等) | 如实报告缺口 + 最小前置 | 给补齐命令或降级路径,不推断 |

> **同类原因第二次出现** → 不是运气问题,是规则缺口:按 [C2-quality.md §7.5](C2-quality.md) 回写对应层,把这次教训固化成锁,下一轮直接命中。
