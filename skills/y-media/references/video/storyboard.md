# 分镜方法论 · Storyboard Methodology

> **定位**:y-media 的**主方法论**。定义如何把 brief 变成一份具体的分镜文档和可直接提交的视频 prompt。它是一套通用的、与品类无关的短视频方法论(带货、种草、品牌故事、产品演示、教程、ASMR、情感叙事等)。
>
> **与配套文档的关系**:
> - 音频设计(人声/环境音/BGM 三层)→ [audio-design.md](audio-design.md)
> - 字幕规范(用不用/动效/音效)→ [subtitle-spec.md](subtitle-spec.md)
> - Prompt 拼接(八要素 + 分镜列映射 + 负向)→ [prompt-craft.md](prompt-craft.md)
> - 模型能力(M1-M6 + 影视术语 + 镜头库 + 反模式)→ [media-rules.md](media-rules.md)
> - 完整示例(晨雾森林雄鹿与幼鹿)→ [example.md](example.md)
> - 场景模板(自然/生活/人像/美食/商业)→ [scenes/](scenes/)

## §0 五条核心原则(R1-R5) — 先读

这五条原则把短视频规划的经验浓缩成锋利的决策规则。它们适用于 y-media 产出的**每一支**视频,无论是否商业。

| # | 原则 | 展开 |
| --- | --- | --- |
| **R1** | **一次定路径,然后坚定执行**:尽早选剪辑 vs 生成 vs 混合;不要在段中切换 | §3 |
| **R2** | **故事驱动,而非清单罗列**:把参数装进骨架 A/B/C,以叙事方式交付;1 段 ≤ 1-3 个关键点 | §4 |
| **R3** | **视听双轨**:① 字幕可选(若画面承载 70% 信息,质感/ASMR/情感可省);若使用,锁定一套风格;② 三层音频(人声·环境音·BGM)必须全部设计 | [subtitle-spec.md](subtitle-spec.md) + [audio-design.md](audio-design.md) |
| **R4** | **7 秒内回收钩子**:视觉爆发或情绪爆发,二选一;7 秒后完播率下降 | §4.5 |
| **R5** | **零错字、品牌名逐字**:品牌名/型号/成分名逐字核对;若用户给了官方拼写,必须原样使用 | [subtitle-spec.md §7](subtitle-spec.md) |
| **R6** | **事件逻辑自洽**:场景/动作/时间/天气/服装必须相互一致,不出现"车间请客吃饭喝酒""下雨天露天吃火锅"这类违反常识的组合 | §5.6 |

## §1 文档结构(侧车只 3 段)

每段视频产出一个 Markdown 文件,保存在预期输出旁边:`<name>.video-brief.md`,其中 `<name>` 与视频的 `output.filename` 主干一致。

**侧车顺序固定**(只 3 段;`## 3-5` 顺序按 brief 需要可灵活,但 `Final Prompt` 一定在最后):

| # | 区块 | 必填 | 说明 |
| --- | --- | --- | --- |
| 1 | **视频主要目标** | 必填 | 一行:`产品/主题 × 人群 × 目标(认知/兴趣/转化) × 骨架(A/B/C) × 时长 × 画幅(默认9:16竖屏)` |
| 2 | **分镜表格** | 必填 | 每镜一行,列定义见 §7。表头锁定 `默认假设` / `音频策略` / `美学母体` / `视听路线` |
| 3 | **Final Prompt(执行层 · 提交给 t2v 模型)** | 必填,**始终放最后** | 一个代码块中的完整多镜 prompt,外加 BGM 备注;`Action` 与 `Camera language` 段按 §2 表格镜号 1:1 对应(见 §5) |

> **§2 表格下可选的扩展项**(不破坏 3 段结构):
> - **Negative Prompt**:进 §3 `Final Prompt` 内的 `Negative constraints:` 块(见 [prompt-craft.md §10](prompt-craft.md));commerce/人像/品牌必填
> - **Inputs**(i2v/kf2v 参考图/起止帧):进 §1 表头的 `默认假设` 行或 §2 表头注释
> - **Generation** 元数据(Provider/model/task.id/参数/warnings/timing):由 Step 7 追加到 §3 之后,作为「## Generation」段(也可作为 §3 的同级段落)

完整可工作的示例见 [example.md](example.md)。

## §2 Brief 解构

把 brief 解析为三个槽位,并用明确的默认值补缺(在文档表头 `默认假设` 行记录):

| 槽位 | 需要确定什么 | 未知时的默认值 |
| --- | --- | --- |
| 主题/产品 | 主体,1-3 个关键点或卖点,可用的素材 | 取自请求;确实缺失时问一次 |
| 人群/受众 | 受众,他们的痛点或兴趣 | 该主体类型的常见受众 |
| 目标 | 认知(brand) / 兴趣(seeding) / 转化(conversion) | 根据请求决定,无固定默认值 |

目标决定基调、节奏和字幕路线。三种目标地位平等;这里不预设商业场景。

## §3 路径判定(剪辑 vs 生成 vs 混合) — 决策一次后贯穿整片

R1 要求"早定路径,生剪不混",这里给出**二元决策表**。在填写分镜表前**先回答两个问题**:

| 判定问题 | 是 → 路径 | 否 → 路径 |
| --- | --- | --- |
| Q1. 主体是否需要真实人出镜(主播/演员/客户本人) 或 是否已有可用的实拍素材(产品 demo / 工厂线 / 仓库 / 街拍) | **剪辑路径(edit)** — 走 CapCut / iMovie / Premiere / ffmpeg,加字幕 + BGM + 调色;**y-media 不生成视频**,只产 storyboard + 剪辑菜谱 | 进入 Q2 |
| Q2. 主体是产品/概念/角色/场景(无实拍可用),且接受 AI 生成美学 | **生成路径(generate)** — 走 t2v / i2v / kf2v,完整流程 | — |

> **决策一次后,整条视频全程不混用**。禁止:同一段前 5s 走 t2v、后 5s 走实拍拼接;若必须拼,按"分段路径"标记,每段独立决策、独立走 Provider 路由、独立 sidecar 记录。

### §3.1 三条路径详解

| 路径 | 触发 | 主体保真度 | 成本 | 输出 | y-media 内部动作 |
| --- | --- | --- | --- | --- | --- |
| **G 纯生成** | 无实拍/无真人/IP 角色/概念演示 | 取决于 i2v 一致性 + prompt 锁定 | 1 段 1 调用 | 视频 mp4 | §4-§8 完整 storyboard + prompt → Provider |
| **E 纯剪辑** | 已有实拍素材/真人出镜/产品 demo 实拍 | 与素材完全一致(无漂移) | 0 调用,1 剪辑工程 | 视频 mp4 + 工程文件 | storyboard 只含分镜表 + 接续菜谱;prompt 段标 `clip-edit` 跳过 Provider |
| **H 分段混合**(谨慎) | 既有实拍(产品特写)又有 AI 段(场景氛围/概念演示) | 段内一致即可 | 多段多调用 | N 段 mp4 + 拼接菜谱 | 每段独立决策 G 或 E,sidecar 标注 `段-1/段-2/...` 各自路径,§8 split-or-merge 走全流程 |

### §3.2 路径判定反模式

- ❌ **生 → 剪 → 生** 中段切换:主体漂移(同一角色脸/手/颜色变),且每个切换点都会破坏音频节点;R1 显式禁止。
- ❌ **默认走 G 不问用户**:Q1 是的(用户已有 demo 实拍)但 Skill 没问就硬生成,既费额度又丢失实拍质感。
- ❌ **默认走 E 不问用户**:Q1 否的(用户没有素材)但 Skill 假设有,直接给空菜谱。
- ❌ **"剪辑工具里我也能拼"** 作为理由抢 H 决策:用户在 Brief 阶段已声明"全 AI 出片",H 路径就不该出现。
- ❌ **路径不写进 sidecar**:后续追溯时无法判断某段是生成的还是实拍,re-edit 时易错。

### §3.3 路径结果写入 storyboard 表头

Brief header 必填一行 `生成路径`,三选一:

```
生成路径: G (纯生成,默认推荐)  |  E (纯剪辑)  |  H (分段混合,需分段子路径)
```

H 路径额外在分镜表前加 `段-1/段-2/...` 分组,每组标子路径;拼接菜谱按 §8 split-or-merge 流程走。

## §4 叙事骨架(A/B/C 三选一)

先选一个骨架;骨架决定镜头数、节奏和字幕路线。

| 骨架 | 用途 | 镜头数 | 单镜时长 | 字幕 |
| --- | --- | --- | --- | --- |
| **A: showcase** (测评/利益/ASMR/变装/演示) | 信息密集、节奏快 | 9-12 | 1.0-2.5s | 含字幕 |
| **B: narrative** (情感/故事/溯源/品牌) | 情绪弧线、节奏较慢 | 5-8 | 2.0-5.0s | 无字幕或极简 |
| **C: 共情子型** (共情/自嘲/治愈/打工人式) — B 的情绪强子型 | 情绪共鸣;共情→自嘲→转折→金句 | 6-10 | 2.0-4.0s | 含字幕 |

适用于所有骨架的规则:

- 每 15s 保持 **1-3 个关键点**;再多就需要拆段(§8)。
- **前 7 秒内回收钩子**(视觉爆发或情绪爆发),否则完播率下降。
- 在封面级镜头上标 `★`;一个 15s 段至少 5 颗,最少每 3s 一颗。

### §4.1 骨架 A · showcase(测评/利益/ASMR/变装/演示)

**核心**:快切、平行、卖点罗列。9-12 镜,单镜 1.0-2.5s,配含字幕路线。

**典型 15s 结构**:

```
镜1 1.5s 钩子   极近景/低角度仰拍   ★  字幕①钩子(痛点/悬念/反常识)
镜3 1.8s 卖点1  微距特写            ★  字幕②数据卖点1
镜5 2.5s 卖点3  低角度侧逆光/缓抬   ★  字幕②卖点3 或 ③背书
镜7 2.0s 高潮   内部微距/捕捉快动作 ★  字幕②核心数据爆点(7 秒高潮镜)
镜8 1.0s 收尾   全景顶部            ★  字幕④CTA(点+利益+紧迫)
—— 15s / 8-12 镜 / ★≥5 / 字幕覆盖①②④
```

### §4.2 骨架 B · narrative(情感/故事/溯源/品牌)

**核心**:线性、起承转合、情绪弧。5-8 镜,单镜 2.0-5.0s。产品作"情绪触发器",不罗列参数。

**典型 15s 结构**:

```
镜1 2.5s 起·铺垫  特写/推镜       ★  字幕①悬念(时间/地点/心声)
镜3 3.0s 承·揭示  特写/平摇       ★  字幕③背书(品牌/情感tag)
镜4 3.0s 承·冲击  特写/手持微晃   ★  字幕⑤情绪tag(泪目/颤抖,面部特写非产品)
镜5 2.5s 转·推进  过肩/慢推       ★  两主体互动(戴戒/递物/拥抱)
镜6 1.5s 合·定格  中景/缓拉焦外   ★  字幕④品牌slogan(替代硬CTA)
—— 15s / 5-8 镜 / ★≥5 / 字幕覆盖①③④
```

**B 的取向**:情绪爆点镜给面部特写而非产品;7 秒高潮是情绪反转不是视觉爆点;对白+环境音+BGM 情绪节点成对出现;结尾用品牌 slogan/情感 tag 而非"小黄车立减"。

### §4.3 骨架 C · 共情子型(B 的强情绪变体)

> **C 是 B 的子型,不是独立骨架**。当 B 的情绪重点是"共情/自嘲/打工人式"时使用 C。三条 C 独有的节奏规则:
>
> 1. **情绪色温对撞**:压抑段(起/承)用冷灰蓝+荧光白(现实感),治愈段(转/合)用暖黄橙(反差治愈);换色点正好落在转折拍,光影同步从硬冷光过渡到柔暖光
> 2. **7s 数字/反差爆点**:不要视觉爆点,要"数字/反差"作为情绪爆点(如"八千五"vs"才三千");数字爆点前 0.5-1s 全断(静音法则 M1)
> 3. **末镜金句/反问留白**:不写硬 CTA,改用黑底金句(末镜或黑屏)+ 关键词黄底高亮;设问引导互动

**四拍节奏表**:

| 拍 | 情绪 | 时长占比 | 职责 | 音频 |
| --- | --- | --- | --- | --- |
| 起 | 共情/痛点 | ~25% | 真实疲惫细节直入, 7s 内出钩子 | 环境音 + 纯OS心声 |
| 承 | 自嘲/吐槽 | ~35% | 荒诞细节堆叠, 节奏渐快 | BGM 鼓点渐重, 音画卡点 |
| 转 | 治愈/温柔 | ~25% | 情绪软着陆, 画面转亮 | BGM 切换, 前 0.5-1s 静音留白 |
| 合 | 金句/收尾 | ~15% | 黑底金句字幕收束 + 互动设问 CTA | BGM 淡出只留环境音 |

**C vs B 的取舍**:

| 维度 | B (普通剧情) | C (共情子型) |
| --- | --- | --- |
| 情绪节奏 | 平缓弧线 | 起承转合(更陡) |
| 7s 钩子 | 氛围/人物出场 | 疲惫日常 + OS 心声 |
| 末镜 | 品牌 slogan/情感 tag | 黑底金句 + 互动设问 |
| 字幕策略 | 无字幕或极简 | 含字幕(3-5 条:钩/转/合拍金句) |
| 适用文案 | 治愈/静谧/品牌感 | 上辈子/破防/家人们/打工人 |

### §4.4 骨架速选(决策树,2 步定位)

```
Step 1: 目标是否是"转化/带货/强信息"?
   是 → 骨架A (showcase · 密信息快节奏)
   否 → 进入 Step 2

Step 2: 主体是否有"人物/故事/情绪弧"?
   是 → 骨架B (narrative · 慢切) 或 骨架C (B 的共情子型)
        —— 情绪以"克制/美感"为主 → 骨架B
        —— 情绪以"共情/自嘲/金句"为主 → 骨架C
   否 → 骨架A (美学导向的 showcase 同样适用)
```

> **判断口诀**:看文案里的情绪词。"高性价比/爆款/必入"是 A;"治愈/静谧/品牌感"是 B;"上辈子/破防/家人们"是 C。**先定骨架,再填表**。

### §4.5 钩子模板(置于镜头表顶部作对照)

| 场景 | 开场视觉 | 文字/音效 |
| --- | --- | --- |
| 测评/演示 | 疑问前置字幕 + 产品全景 | "这个很火的到底好不好用?" |
| 利益/转化 | 价格锚点 + 产品硬切 | 大字幕 "3.9元包邮" |
| ASMR/感官 | 感官特写 + 撕包装/切开音效 | 无口播,全声音 |
| 溯源/故事 | 场景直入 + 人物出镜 | "刚下火车来看娃" |
| 品牌/形象 | 氛围场景 + 品牌元素 | slogan 前置 |
| 共情/自嘲(C) | 疲惫日常直入 + 内心 OS 字幕 | "上辈子到底造了什么孽" |

## §5 镜头结构(规划层 vs 提交层) — 关键

### §5.1 默认规则(1:1 镜号对应)

上面的镜头数(5-12)是**规划层**数字,用于分镜表和人工评审。**提交层**(写到 `Final Prompt` 里的内容)默认按 §4 表格 1:1 对应:**每个分镜一行,每个镜号一个时间段,动作与镜头语言两段都用同一组时间锚点**。

| 生成模式 | 镜头结构写法 | 时间表达 | 说明 |
| --- | --- | --- | --- |
| **单段直出 t2v**(y-media 默认) | 按 §2 表格 1:1 对应;**禁止主动合并** | 时间锚点(每个镜号一段) | 镜号与时间段一一对应,镜头边界、主体动作、转场最清楚 |
| **多段生成 + 剪辑**(拆段 + 拼接) | 每段独立表达自己的镜头结构 | 每段独立 | 超过 Provider 单段硬上限时使用 |
| **剪辑式密集切**(骨架A 带货) | 规划层保留完整快切结构 | 需要多段生成 + 人工剪辑 | 不把快切剪辑强塞进单段直出 |

**规则(默认)**: `Final Prompt` 的 `Action` 段和 `Camera language` 段都按 §4 表格的镜号 1:1 展开,每个镜号一个时间锚点。

### §5.2 唯一允许合并的情形(三项必须同时满足)

1. `target_duration > capability_limits[<capability>].maxSingleSegmentDuration`,且
2. 已与用户完成 §8.1 的 split-or-merge 确认(默认是「分开」,不走合并),且
3. 合并后**段内每个镜号在 prompt 里仍可识别**(用 `S01-02 → S01-03 merged` 显式标注,不让模型猜)。

### §5.3 反例(禁止的合并)

6 镜 → 3 段时间段(0-5/5-11/11-15);合并后段内含 2 个独立镜号 + 多次切镜 + 1 次转场,模型会拉长转场、淡化硬切、反转情绪被抹平。**§4 表格的镜号是创意层的最小表达单元,合并是覆盖,不是简化。**

### §5.4 时间表达方式(3 种,按需选)

| 方式 | 强度 | 写法 | 适用 |
| --- | --- | --- | --- |
| 精确时间锚点 | 最强 | `0.0-5.0s: ...` | 镜头边界、动作阶段或转场需要明确时 |
| 画面编号 | 中等 | `Scene 1: ...` | 多个画面单元需要分层描述时 |
| 动作流连接词 | 弱/自然 | `then` / `suddenly` / `as` | 单一连续动作或短段落 |

### §5.6 事件逻辑自洽性(R6 反例库)— 5 维矩阵 + 修复参考

**核心原则**:场景 / 动作 / 时间 / 天气 / 服装 / 道具必须**相互一致**,违反常识的组合一旦出现,短视频观众一眼识破,信任度归零。**这一类问题不会由质检发现,因为"画面已出,无法修改"**——必须在分镜表规划阶段就把好关。

**R6 不集中在这里自检**:R6 拆到各环节的 DoD(就近执行),本节是反例库 + 5 维矩阵的来源说明,各步具体检查项见:

| 环节 | R6 在该步的具体检查项 | 文档 |
| --- | --- | --- |
| 写故事(step 1) | 事件本身合理:5 维组合不出现反例 | [§5.6.1 / §5.6.2](storyboard.md) |
| 定人物(step 2) | 服装-场景匹配;身份-动作匹配;气质-情绪匹配;年龄-场景安全性 | [character.md §4](character.md) |
| 定场景(step 3) | 场景类型内部一致;时代-光线匹配;天气-场景匹配;风格锚-场景匹配 | [scene.md §6](scene.md) |
| 写脚本(step 4) | Final Prompt 继承前 3 步的 R6 结论,不漂移 | [prompt-craft.md §1 八要素表](prompt-craft.md) |
| 评审过审(过门) | **不复看 R6**——只检模型/格式/规则 | [media-rules.md §4](media-rules.md) |

#### 5.6.1 五维一致性矩阵(本步执行摘要)

| 维度 | 必须一致的字段 | 常见冲突 |
| --- | --- | --- |
| **场景** | 地点类型(室内/户外/车间/办公室/餐厅) | 车间 ≠ 餐桌;厨房 ≠ 客厅沙发 |
| **时间** | 时段(晨/午/黄昏/夜) + 季节 | 黄昏 ≠ 雪地;冬季夜 ≠ 短袖 |
| **天气** | 晴/雨/雪/雾 | 露天雨景 ≠ 头顶无遮挡(除非有雨棚/伞) |
| **服装** | 与场景/季节匹配 | 车间作业服 ≠ 礼服;厨房烹饪 ≠ 睡衣 |
| **动作** | 与场景/服装/道具匹配 | 车间请客吃饭喝酒 = 错;雨天露天吃火锅 = 错 |

#### 5.6.2 典型反例与修正

| 反例 | 错在哪 | 修正 |
| --- | --- | --- |
| 车间里摆圆桌请客吃饭喝酒 | 场景(车间)与动作(宴请)矛盾;车间是产线作业,无餐桌也无客 | 改为"车间工人下班后的小聚"或"车间团建茶歇" |
| 下雨天露天吃火锅 | 天气(雨)与场景(露天)矛盾;雨直接落进锅里 | 加雨棚/伞/改为室内;或换晴天 |
| 黄昏拍摄雪地雪景 | 时间(黄昏,光线暖)与场景(雪地,强反光)冲突,且季节暗示矛盾 | 改"雪后清晨低角度光"或"雪夜路灯暖光" |
| 厨房里穿西装做菜 | 服装(西装)与动作(厨房操作)矛盾 | 改围裙 + 居家服,或把场景改为宴会厨房 |
| 沙漠里出现常绿阔叶林 | 场景(沙漠)与植被(阔叶林)矛盾 | 改为"沙漠绿洲椰枣林"或"温带森林" |
| 写字楼天台 4 月 露天烧烤 | 季节(4 月气温)与天气安全性矛盾 | 改"夏季傍晚楼顶 BBQ + 灯光"或"室内烤盘" |

#### 5.6.3 步 1(写故事)聚焦检查项

填完分镜表骨架后,逐项回答,任一为否就回头改:

1. **场景与动作匹配吗?** —— 这个地点真的能发生这个动作吗?(如:车间能"作业",不能"宴请")
2. **时间/天气与场景/服装匹配吗?** —— 黄昏 + 雪地、雪夜 + 短袖 = 必错
3. **服装与动作匹配吗?** —— 礼服 + 车间、围裙 + 宴会厅 = 必错
4. **道具与场景匹配吗?** —— 户外 + 蜡烛(无挡风) = 必错;雨天 + 纸质文件 = 必错

> 服装-场景细表见 [character.md §4.2](character.md);时间-天气-光线细表见 [scene.md §6.2](scene.md);天气-场景细表见 [scene.md §6.3](scene.md)。本节 4 问是执行版。

#### 5.6.4 步 4(写脚本)承接

Final Prompt 的 `Scene` 段(场景三层)与 `Action` 段(动作 + micro-action)必须**继承 step 1-3 的一致性结论**:
- 场景三层里的**光线/天气**字段必须与 step 1 的时间/天气结论一致
- 角色四层里的**服装**字段必须与场景/动作一致
- 任一维度漂移,视为 prompt 不合格,不提交

#### 5.6.5 写作铁律(5 条)

完整 5 铁律见 [prompt-craft.md §5](prompt-craft.md)。本文件不重复,只列**与镜头结构强相关的两条**:

1. **动作写慢写连续**:每一镜单动作 + 至少 1 个 micro-action;长时段拆 2-3 拍,避免静止动词
2. **运镜写稳写简单**:一镜至多 2 个运镜;不写手持抖动 / 甩镜(模型易跑偏)

其余 3 条(约束焊死 / 术语转换 / 风格锚定)见 [prompt-craft.md §5.3-§5.5](prompt-craft.md)。

## §6 15s 段落规划指标(per-skeleton 速查 + 非 15s 比例换算)

> **这是 §4 骨架表的规划层浓缩版**,填表前 30 秒对一遍,填完后 1 分钟自检。**展示层数字,执行层语义化降级**(见 §7.1)。

### §6.1 per-skeleton 速查表(15s 默认段)

| 指标 | 骨架A (showcase · 密信息) | 骨架B (narrative · 慢切) | 骨架C (共鸣 · B 的共情子型) |
| --- | --- | --- | --- |
| **镜头数(规划层)** | 9-12 镜 | 5-8 镜 | 6-10 镜 |
| **单镜时长** | 1.0-2.5s(密) | 2.0-5.0s(慢) | 2.0-4.0s(中) |
| **★ 密度(15s 段)** | ≥5 ★,每 3s 一颗 | ≥4 ★,首镜/中点/末镜必 ★ | ≥5 ★,四拍各 1 |
| **★ 分布** | 钩子镜 + 卖点镜 + 价格镜 + CTA 镜 + 1 个转场 | 钩子镜 + 关系镜 + 高潮镜 + 收尾镜 | 起/承/转/合 各 1 ★ |
| **7s 钩子位置** | 0-2s 钩子镜(疑问/价格/感官) | 0-3s 钩子镜(氛围/人物出场) | 起拍 0-2s(疲惫细节直入) |
| **7s 钩子形式** | 视觉钩(硬切) 或 字幕钩(疑问前置) | 视觉钩(氛围) 或 情绪钩(人物回头) | 视觉钩(疲惫日常) 或 情绪钩(OS 心声) |
| **段均运镜变化** | 4-5 种(快切需要) | 2-3 种(慢切克制) | 2-3 种(每拍 ≤1 种) |
| **段均字幕数** | 4-6 条(钩/卖点/数据/CTA) | 0-2 条(无字幕或极简) | 3-5 条(钩/转/合拍金句) |
| **音频节点** | 3-5 个(钩子音效+卡点+CTA) | 1-2 个(起/收) | 4 个(每拍 1 个情绪节点) |
| **主线 KPI** | 完播 + 点击转化 | 完播 + 互动(评论) | 完播 + 收藏 + 转发 |

> **注**:镜头数是**规划层**上限。提交层(prompt)按 §4 表格 1:1 对应,**默认不合并相邻镜头**;只有满足 §5.2 列出的三项条件时才能合并,合并后需在 prompt 里显式标注镜号。

### §6.2 自检 4 问(填完表后逐条过)

1. **★ 密度达标了吗?** 15s 段 < 4 颗 = 信息密度不够,补一颗"卖点镜 ★"或"价格镜 ★"。
2. **7s 钩子是真的"钩"吗?** 钩子镜的视觉/字幕要能在 0.5s 内抓住注意力,不是"产品缓缓入画";不达标就重写钩子镜。
3. **每条 ★ 镜都有 ★ 应有的内容吗?** 一颗 ★ 至少包含 ① 主体清晰 ② 视觉重点 ③ 美学母体 ④ 可裁切为竖版封面。
4. **时长加和 == 目标时长?** 每镜时长 0.1s 精度,段总和 = 目标(15.0s / 18.0s / 30.0s);不匹配就调整最短或最长镜,不动骨架。

### §6.3 非 15s 段的比例换算

| 目标时长 | 镜头数(规划层) | ★ 数 | 7s 钩子数 |
| --- | --- | --- | --- |
| 5s | 3-4 镜 | ≥2 | 1 |
| 10s | 5-8 镜 | ≥3 | 1 |
| 15s(默认) | 6-12 镜 | ≥4-5 | 1 |
| 20s | 8-14 镜 | ≥6 | 1-2(7s+14s) |
| 30s | 12-20 镜 | ≥8 | 2(7s+20s) |
| 60s | 24-40 镜 | ≥15 | 4(7s+20s+35s+50s) |

> 超过 Provider 单段硬上限时(查 `capability_limits[<capability>].maxSingleSegmentDuration`),走 §8.1 split-or-merge 流程,不要靠堆 30s 段实现。

## §7 分镜表列(Shot Table Columns)

每一镜都要填满每一列。精确胜过散文;每列回答一个问题。

| 列 | 规则 | 示例 |
| --- | --- | --- |
| 镜号 | 从 `S01-01` 起 | S01-03 |
| 时长 | 精确到 0.1s;段总和与目标时长一致 | 1.8s |
| 景别与视角 | 景别 + 机位角度 | 微距特写,低角度仰拍 |
| 运镜 | 运镜 + 速度 + 方向;一镜至多 2 个动作 | 缓推,跟随虾仁滑落 |
| 光影 | 方向 + 色温 + 光比 + 光质 | 45°侧光,6000K,柔光高对比 |
| 色彩 | 主色 + 辅色 + 色调 | 青白+冰蓝,冷调 |
| 主体动作 | 具体、单一的动作 | 手撕开冷冻包装袋,冰块碎粒滑落 |
| 道具/环境 | 前景/中景/背景 三层; ≥3 可命名元素; 1 个光源; 背景加 1-2 个低速动态元素 | 前景冰块碎粒/中景包装袋/背景厨房台面虚化+水珠 |
| 音频三层 | ① 人声(有对白/OS心声/无对白) ② 环境音+关键音效点(镜次+时机+音效名) ③ BGM 节点 | (环境)撕包装"嘶啦"+冰块碰撞"咔啦"/(BGM)木吉他扫弦淡入 |
| 屏显字幕 | [subtitle-spec.md](subtitle-spec.md);仅在无字幕路线留空 | ①"这虾仁,也太鲜了!"·上1/3·弹入放大 |
| 视觉重点 | `★` = 封面级 | ★ |

**环境真实感**(任何上镜环境都适用 `3+1` 规则):`[具体场所] + [3 个可命名道具/纹理] + [1 个光源方向色温]`。避免纯渐变或空棚背景;加入生活痕迹,画面才不会冻住。每个场景从四种动态中选 **1-2 个缓慢的局部动态元素**:

| 动态类型 | 示例 |
| --- | --- |
| 人物动态 | 背景虚化人流走动 / 邻桌客人交谈 |
| 自然动态 | 纱帘轻飘 · 树影摇曳 · 水面波光 |
| 光影动态 | 光斑缓移 · 明暗呼吸 · 屏幕微闪 |
| 粒子动态 | 蒸汽升腾 · 尘埃浮动 · 水汽 |

### §7.1 颗粒度标尺(Granularity Scale)

每一列都必须填到下面的颗粒度。抽象形容词("暖光""柔和""自然")会失败,因为模型没有可锁定的参数。具体数值("4500K""光比2:1""-18dB")会成功,因为它们钉住了模型的输出。完整标尺见 [media-rules.md](media-rules.md);F1-F12 阈值见 [../influence-factors.md](../influence-factors.md)。

| 字段 | 抽象(拒绝) | 具体(接受) | 阈值来源 |
| --- | --- | --- | --- |
| 光影·色温 | "暖光" | `4500K` (具体K值) | F3 |
| 光影·光比 | "柔和" | `2:1` (数字比) | F3 |
| 光影·光质 | "好看的光" | `柔光` / `硬光` / `半硬` | F3 |
| 光影·光位 | "侧面" | `45°侧光` / `150°逆光` (角度) | F3 |
| 色彩·饱和 | "鲜艳" | `饱和度+10` (±数值) | F4 |
| 音频·音量 | "轻柔" | `-18dB` (具体dB) | F6 |
| 音频·BPM | "中速" | `95BPM` (数字) | F6 |
| 音频·音效 | "蹄声" | `嗒嗒` (拟声词) | F6 |
| 运镜·速度 | "缓慢" | `0.3m/s` (量化速度) | F2 |
| 主体 | "一匹小马" | `约6个月大的小马驹,棕白相间,鬃毛蓬松,四肢修长` (≥3特征) | F1 |
| 焦段 | "广角" | `16mm广角` / `85mm中焦` (等效mm) | F5 |
| 约束 | "要有高级感" | `24fps,快门180°,禁止文字` (可执行) | F10 |

### §7.2 展示层 vs 执行层(Display vs Execution)

| 字段 | 展示层(分镜表,人读) | 执行层(prompt,模型读) | 降级规则 |
| --- | --- | --- | --- |
| **色温** | 4500K | `soft golden morning backlight` / `cool blue hour diffused light` | K值 → 光源描述 |
| **光比** | 3:1 | (删除)用光源方向替代: `rim/backlight with soft sky fill` | 数字 → 方向 |
| **光质** | 柔光 / 硬光 | `soft diffused light` / `hard direct light` | 保留语义词 |
| **光位** | 45°侧光 / 150°逆光 | `side light from the left` / `backlight from behind` | 角度 → 方位词 |
| **饱和度** | 饱和度+10 | (删除)用风格标签替代: `vibrant colors` / `muted tones` | 数字 → 风格词 |
| **音量** | -18dB | (移出 prompt,进 `Notes for downstream audio`) | 数字 → 删除 |
| **BPM** | 95 BPM | (移出 prompt,进 `Notes for downstream audio`) | 数字 → 删除 |
| **音效拟声** | 嗒嗒/唰/噗噗 | (移出 prompt,进 `Notes for downstream audio`) | 拟声词 → 删除 |
| **主体月龄** | 约6个月大 | `a 6-month-old ... foal` (保留,模型理解) | 数字描述保留 |
| **焦段** | 16mm-85mm | (作为风格参考保留) `shot on ARRI Alexa with shallow depth of field` | 焦段 → 摄影机 |
| **运镜速度** | 0.3m/s | (删除)用运镜语义替代: `slow` / `moderate` / `fast` | 数值 → 形容词 |
| **帧数** | 361 (8n+1,默认 15s) / 433 (8n+1,封顶 18s) | (不写进 prompt,进 API 参数) | 数字 → API参数 |
| **镜头结构** | N 镜(规划) | N 个时间锚点(执行) | **1:1 镜号对应,默认不合并**(例外见 §5.2) |

### §7.3 三层划分总结

| 层 | 用途 | 读者 | 关键字段 |
| --- | --- | --- | --- |
| **展示层** | 分镜表 + 创作规划 | 人(导演/客户/归档) | 具体数字(K/dB/BPM/月龄/焦段/拟声词) |
| **执行层** | 提交给 t2v 模型的 prompt | 模型 | 语义化描述(soft golden / BBC Earth / slow dolly-in) |
| **音频笔记层** | 供下游音频制作 | 人(后期) | BPM/dB/拟声词/环境音优先级 |

**铁律**: 展示层的数字不写进 prompt(模型忽略 M4);执行层不写 dB/BPM(模型无效 M6)。

| 主体类型 | 模板 | 关键要点 |
| --- | --- | --- |
| 自然 / 动物 / 治愈系 | [scenes/scene-nature-animal.md](scenes/scene-nature-animal.md) | 骨架B慢切 + 无字幕 + 黄金时刻光 + 清新民谣BGM |

| **商业带货 / 产品演示(6 大品类)** | [scenes/scene-commerce-product.md](scenes/scene-commerce-product.md) | **骨架A showcase + 含字幕 6 类全用 + R5 零错字铁律 + 合规清单**;美妆个护/服饰/家居/数码/母婴/通用 |

## §8 时长与分段策略

- **单段默认**:优先一段。硬上限是**动态的**,不是固定的 — 见 §8.1。
- **帧数映射**:`num_frames = round(duration_seconds * frame_rate)`。帧数必须满足所选 Provider 的 `maxFrames` 上限与 `frameCountRule`(如 `8n+1`)。从 `capability_limits` 读取当前 Provider 的 `maxFrames` 和 `maxSingleSegmentDuration`;**不要在任何 prompt 或 storyboard 中硬编码 18s/441**。

### §8.1 动态封顶 + 拆分或合并确认(生成前问,按用户选择执行)

**硬上限是动态的,不是固定 18s**。每个 Provider 的单段上限不同,取自 `capability_limits` 中的 `providers[].capability_limits[<capability>]`:

| 字段 | 来源 |
| --- | --- |
| `maxSingleSegmentDuration` | `capability_limits[<capability>].maxSingleSegmentDuration` |
| `maxFrames` | `capability_limits[<capability>].maxFrames` |
| `frameCountRule` | `capability_limits[<capability>].frameCountRule` |

这些字段由各 Provider 的 [providers/manifest.cjs](../../providers/manifest.cjs) 的 `capability_limits` 段在注册时声明。**禁止在 prompt / storyboard / 决策树里硬编码 18s/441**。

**触发条件**: `target_duration > providers[].capability_limits[<capability>].maxSingleSegmentDuration`。

**流程:生成前问,按用户选择执行**

1. **规划** 时检测到目标 > 封顶,**暂停** §3 Plan
2. **确认门** — 给出二选一(用 AskUserQuestion 工具):
   - **① 分开 (默认推荐)** — 拆成 N 段独立交付,每段都是有效产物;sidecar 不附拼接菜谱
   - **② 合并** — 拆成 N 段独立生成 + sidecar `Generation` 段附外部工具拼接菜谱(CapCut 时间线对齐 / iMovie 拖拽 / ffmpeg `-f concat -i list.txt -c copy` 三选一);**由用户自拼**
3. **执行** 用户选择后,提交 N 段(每段独立走 Provider 路由)
4. **禁止 skill 内部合并** — 运行时无 ffmpeg 假设

**确认模板**(向用户提问时直接用):

```
目标时长 X 秒 > Provider 封顶 Y 秒(读自 capability_limits)。需要您选:
  ① 分开 (默认) — N 段独立交付,各段都是有效产物,不再合并
  ② 合并 — N 段 + sidecar 附 CapCut/iMovie/ffmpeg 拼接菜谱,您自己拼
```

**禁止的反模式**:

- ❌ 把 18s / 441 硬编码到 §8 或 prompt — 不同 Provider 不同
- ❌ 不问用户就默默拆段 — 抢决策
- ❌ 默认走 ① 不问 — 剥夺用户选 ② 的机会
- ❌ skill 内部尝试合并 — 运行时无 ffmpeg 假设
- ❌ 拆完 N 段后才问"要不要拆/怎么拼" — 生成已花额度,且 N 段已交付,"分 vs 合"已隐含决定

### §8.2 帧数校验(8n+1 规则)

主流 t2v 模型(Agnes/Seedance/Wan/Sora/Veo)的帧数约束以 `capability_limits` 为准:

```
约束 1: 帧数 ≤ capability_limits[<capability>].maxFrames
约束 2: 帧数满足 capability_limits[<capability>].frameCountRule (如 8n+1, n = 0,1,2,...)
```

读法: 通过 `listCapabilities` 读取 `providers[].capability_limits`。

**帧数速查(以 Agnes 24fps 为例,其他 Provider 见 capability_limits)**:

| 时长 @24fps | 帧数 | 合规 | 角色 |
| --- | --- | --- | --- |
| 5s | 121 | ✓ (8×15+1) | 最小叙事单元 |
| 10s | 241 | ✓ (8×30+1) | — |
| 15s | 361 | ✓ (8×45+1) | **默认规划刻度**(留 3.4s 裕量到 18s 封顶) |
| 18s | 433 | ✓ (8×54+1) | **封顶档**(接近 441 硬上限) |
| 18.375s | 441 | ✓ (8×55+1) | 理论极限 |
| 20s | 481 | ✗ 超 Agnes 441 上限 | 必拆 |

**校验失败时**:

| 失败原因 | 修复方案 |
| --- | --- |
| 不满足 `frameCountRule` | 微调时长到最近合规值(如 15.0s → 15.04s = 361 帧) |
| 帧数 > `capability_limits[<capability>].maxFrames` | 必拆;**生成前先问用户**走 §8.1 split-or-merge 确认门;不在 skill 内部合并 |
| 时长 ≠ 用户预期 | 优先满足 `frameCountRule`,在 ±0.5s 内调整 |

### §8.4 Provider 选型决策

| 需求 | 首选 Provider | 理由 |
| --- | --- | --- |
| 中文 prompt 友好 | Wan / Seedance | 训练语料中文占比高 |

### §8.5 多段一致性(N 段规划阶段必做)

- 每段独立满足 §4-§7(独立 brief、独立钩子、独立 audio 节点)。
- 段间一致性: 美学母体照抄,后段以前段末帧作首帧,一套锁定的字幕/音频风格。
- 默认**竖屏 9:16**,除非用户另有要求。Provider 支持时,通过 `parameters.width/height`(例如 720x1280)表达。
- 保持时长、帧数与分镜表总和彼此一致。
